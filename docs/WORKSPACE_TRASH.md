# 결과·프로젝트 휴지통 — D-063

기준: PR40 병합 `99a00a0e83271b872e9cb0e0e9d7f41bbc23df9f` (검토 head7d27eef, Windows/Linux CI2/2 직접 확인). 범위는 결과의 논리 숨김/복원, 프로젝트 폴더 이동/복원과 기존 생성 경로의 상호 배제다. 실제 계정 호출이나 영구 삭제를 수행하지 않는다.

## 사용 동선

- 이미지 바로 위 ‘휴지통으로’는 선택 결과만 숨긴다. 같은 자리의 ‘되돌리기’로 직전 결과를 복원한다. ‘휴지통 n’에서 미리보기와 시드로 골라 복원할 수도 있다. 각 성공 단계의 설명 문장은 추가하지 않는다.
- 프로젝트 ‘열기’ 목록에 ‘휴지통으로’와 ‘휴지통’ 탭을 둔다. 현재 프로젝트의 미저장 입력이 있으면 기존 저장/버리기/취소 결정을 먼저 받는다. 이동한 현재 프로젝트는 새 입력으로 전환하며 상단 ‘프로젝트 복원’으로 저장된 상태를 다시 열 수 있다. 그 이후의 복원은 목록의 휴지통 탭에서 한다.
- 생성/준비/참조 처리·미저장 PNG가 있으면 메인에서도 이동/복원을 거부한다. 반대로 휴지통 작업이 worker를 기다리는 동안에는 생성 준비/실행/참조 처리를 시작할 수 없다. 정상 닫기/연결 재시작도 기존 hasWork 경계를 따른다. 이미 전송된 요청의 자동 재시도는 없다.

## 결과: manifest version6의 논리 상태

`images`의 원래 레코드/UUID·PNG 해시·실제 입력·요청 hash를 삭제하거나 바꾸지 않는다. 첫 숨김 때만 version6와 `trashedImageIds: UUID[]`를 추가한다. ID는 images에 실제 존재해야 하며 중복/알 수 없는 키/잘못된 타입은 거부한다. 전체 한도는 숨김 포함120개, PNG/참조 합계256MiB 그대로다. 휴지통은 디스크/보관 슬롯을 비우지 않으며 이 점은 휴지통 안에 표시한다. 용량이 찬 경우 입력만 새 프로젝트로 복제하는 기존 경로를 쓸 수 있다.

- UUID·기대 manifest 리비전·boolean만 IPC로 받는다. 현재 write.lock·리비전 비교·이전 manifest의 불변 이력·wx/0600 임시 파일/fsync/rename을 재사용한다.
- 숨기기는 기존 PNG를 읽거나 지우지 않는다. 복원은 해당 PNG 한 개의 해시/크기를 검사한 뒤 표시를 푼다. 손상이면 숨김을 유지한다. 명시적 열기/복사/복구의 전체 PNG·참조 검사는 계속 적용한다.
- 일반 입력 저장·다음 결과 append·전체 프로젝트 복사·v6 이력 복구는 숨김 목록을 보존한다. 입력만 복제는 결과/숨김 상태를 가져오지 않는다. 복구는 기존처럼 새 UUID다.
- 기존 v1~v5는 계속 읽고, 휴지통을 쓰지 않으면 승격하지 않는다. 모두 복원한 v6도 원래 프로젝트에서는 v6로 유지한다. v6를 모르는 이전 앱은 상위 버전으로 거부하며 숨긴 결과를 조용히 다시 노출하거나 덮어쓰지 않는다.
- 렌더러의 갤러리/카운트는 정상 결과와 휴지통을 분리한다. 휴지통 썸네일은 기존 UUID 한정 읽기·가시 범위/직렬 큐/URL 해제를 재사용한다. 원본 PNG/메타데이터는 그대로다.

## 프로젝트: 전체 디렉터리 이동

`projects-v1/<UUID>`를 같은 파일시스템의 `projects-v1/.trash/<UUID>`로 rename한다. manifest·이력·원본 PNG·참조 원본/파생과 고아 자산도 통째로 남는다. 정상 목록/열기/생성 준비에서는 이동된 프로젝트를 찾을 수 없으며 휴지통 목록에서만 복원한다. 정상/휴지통 목록은 각1000개 한도다. 새 폴더는0700, 경로 성분과 목록의 manifest 읽기는 기존 링크/일반 파일 검사를 따른다. renderer가 경로를 지정할 수 없다.

이동은 원래 폴더의 배타적 write.lock을 만들고 핸들을 닫은 뒤 수행한다(Windows rename). 기존 잠금이면 거부하며 다른 잠금을 지우지 않는다. 정상 종료는 이동된 위치에서 자신의 잠금을 지운다. 복원은 원래 UUID 위치가 존재하면 거부하고 어떤 폴더도 덮어쓰지 않는다. 손상/상위 버전 manifest도 이동/복원 자체로 고치지 않는다. 휴지통 목록은 고정 오류를 표시하고, 복원 뒤 명시적 열기에서 무결성을 다시 검사한다.

프로세스가 rename 뒤 죽어 남긴 잠금은 복원 시 보존한다. 읽기/복사 복구는 기존대로 가능하지만 저장은 잠금 때문에 막힐 수 있다. 자동 잠금 해제는 하지 않는다. rename 뒤 fsync/정리가 실패하면 오류여도 이미 이동됐을 수 있으므로 정상/휴지통 목록을 다시 확인한다. 자동 재전송/재시도는 하지 않는다. 같은 사용자 권한의 외부 악성 프로세스까지 막는 전역 파일시스템 샌드박스는 아니다.

## 생성과 상태 수명

`withProjectMutation`이 첫 await 전에 기존 단일 실행권을 선점한다. 이전 단일/묶음 승인과 latest를 무효화해 오래된 상태 응답이 숨김을 되돌리지 않게 한다. 성공적으로 휴지통에 옮긴 프로젝트의 중단된 메모리 예약은 끝낸다. 다른 프로젝트의 미전송 예약은 보존하되 새 확인을 받는다. 실패/중단된 OS 작업을 자동으로 다시 실행하지 않으며 finally에서 실행권을 해제한다. 파일 변경은 직렬 저장 worker에서 처리한다.
