# 새 작업실의 이미지 생성 (D-041 / D-048)

현재 범위는 저장된 씬의 **V5 Full 또는 기존 V4.5 기본1장 → 원본 PNG 보관 → 다시 열어 표시**다. 새 입력은 V5 Full·832×1216·무작위 시드·23스텝·가이던스7·Euler ancestral/Karras·Standard 품질/Heavy 부정 프리셋으로 시작한다. V5 바인딩 근거와 서버 미확인 항목은 [NAI_V5_BINDING.md](NAI_V5_BINDING.md)에 구분했다.

## 사용 흐름

1. 새 작업실을 연다. 일반 새 프로필은 온라인이며 기존에 저장한 오프라인 선택은 유지한다. 오프라인이면 API 토큰·연결 모드에서 변경하고 재시작한다. mock/명시적 개발 실행의 제한은 그대로다.
2. API 토큰 창에 Persistent API Token을 직접 넣는다. OS 보안 저장이 가능하면 기억하기를 제안하고 세션 한정 선택도 제공한다. 예전 V3 로그인/TOKEN.txt와는 별도이며 키를 채팅/CLI로 보내지 않는다.
3. 프롬프트·부정 프롬프트·시드·모델과 크기/설정을 고른 뒤 **생성**을 한 번 누른다. 입력 저장→메인 준비→1회 전송이 이어지며 별도 전송 확인창은 없다. 앱은 비용/무료 여부·Anlas·Opus 사용량을 계산하지 않으므로 설정별 사용 조건은 NovelAI에서 확인한다.
4. 응답을 기존 ZIP/PNG 검사로 확인하고 원본 PNG와 요청 기록을 저장한다. 결과는 다른 프로세스/오프라인에서도 열 수 있다. 저장만 실패하면 아래 결과 저장 복구를 사용한다.

| 모델 | 요청 크기 | 설정 | 바인딩 |
| --- | --- | --- | --- |
| V5 Full | 832×1216 / 1216×832 / 1024×1024 | 스텝1~50·가이던스0초과~10, 품질 none/light/standard, 부정 none/light/heavy/human/furry | nai-v5-full-v1 |
| 기존 V4.5 Full | 512×512 | 28스텝·가이던스5·태그/프리셋 없음 | nai-v45-basic512-v1 |

품질 태그는 양성 프롬프트 뒤, 부정 프리셋은 부정 프롬프트 앞에 더한다. 직접 같은 태그를 입력하면 추가 안 함을 선택한다. 편집 입력은 그대로 저장하고 실제 요청에는 선택 규칙을 적용한 뒤 해시를 기록한다. 기존 프로젝트를 열 때 모델/설정을 자동으로 바꾸지 않으며 모델을 직접 선택할 때만 그 모델의 기본 설정을 적용한다.

활성 캐릭터·좌표·`|`·`<모음.조각>` 전개는 아직 거부한다. 기존 입력은 읽고 저장할 수 있으며 캐릭터를 삭제하지 않고 명시적으로 비활성화할 수 있다. 반복 실행은 [대기열](WORKSPACE_QUEUE.md)에서 총 건수와 설정을 확인한다. 실제 새 화면의 V5 서버 호출은 이번 자동 검증에서 하지 않았으므로 웹 출력과 같은 품질/모든 파라미터 수용을 보장하지 않는다.

## 실행과 실패

메인은 저장된 UUID/리비전/씬 ID로 요청을 만든다. prepare 전에 오프라인을 거부하고, prepare/run에서 manifest/리비전·남은 잠금·이력/이미지/JSON 한도를 검사한다. D-042에 따라 기존 PNG 본문 전체는 다시 읽지 않으며, 명시적 프로젝트 open/copy/recover에서 전체 해시/크기를 확인한다. 최대 PNG32 MiB를 보수적으로 예약해 공간을 확인하므로 실제 작은 이미지보다 일찍 보관 한도에 걸릴 수 있다. 파일 권한·디스크·다른 프로세스의 후속 변경까지 보장하는 예약 잠금은 아니다.

무작위 시드는 메인 crypto에서 준비 시 한 번 결정해 그대로 전송/기록한다. 반복 확인창에는 확정 시드를 표시한다. 새 씬 기본값은 이미 무작위이며, 사용자가 저장한 고정0도 보존한다. 확인은 5분 만료·1회 사용이며 새 prepare/취소로 이전 확인을 폐기한다. run은 첫 await 전에 확인을 선점한다. 리비전이 바뀌면 보내지 않는다. 프로세스당 한 요청/미저장 결과만 허용하며 자동 재시도는 없다. 네트워크/해제 기한은 기존 sendImage의90초이고 저장 worker I/O까지의 전체 작업 기한이라는 뜻은 아니다.

생성은 defaultSession에 묶인 기존 Electron 전송기만 사용한다. 토큰은 메인에서 읽고 렌더러/worker로 보내지 않는다. 쿠키/리다이렉트/오프라인 차단·ZIP/PNG 제한·원본 바이트 보존은 유지한다. 취소·시간 초과·수신/검증/저장 실패는 `mayHaveReachedServer`를 보존해 서버가 처리했거나 사용량이 소모됐을 가능성을 안내한다. 401/402/429는 고정 안내를 사용하고 서버 본문·OS 예외·내부 응답 사유는 화면으로 보내지 않는다.

PNG 수신 뒤 저장만 실패하면 최대32 MiB 원본을 메인 메모리에1건 유지한다. **결과만 다시 저장**은 최신 manifest를 다시 읽고 같은 결과 UUID가 이미 기록돼 있으면 그 PNG 한 장의 해시·기록 크기를 확인한 후에만 메모리 결과를 해제해 중복 추가하지 않는다. 해당 파일이 손상됐으면 미저장 결과를 유지한다. **입력·이번 결과만 새 프로젝트로 저장**은 준비 당시 입력/씬과 이번 PNG만 새 UUID에 저장하며 이전 PNG·원본 잠금/파일은 건드리지 않는다. 원래 프로젝트의 이미지까지 복구했다고 표시하지 않는다. worker 중지라면 이 영역에서 저장 기능을 명시적으로 다시 시작한 뒤 저장을 별도로 고른다. 미저장 PNG를 버리려면 별도 선택을 확인한다.

메모리 결과는 프로세스 종료/재시작 뒤 복구할 수 있는 내구성 저장이 아니다. 저장 실패 때 창을 강제 종료하지 않는다. UI의 busy 상태 외에도 메인의 정상 finish/연결 모드 재시작이 진행 요청·미저장 PNG를 확인해 거부한다. renderer crash/unresponsive의 native dialog에서 명시적으로 버리고 닫는 선택은 유지하며 메모리 PNG 손실 가능성도 안내한다.

## 저장 형식 v1/v2/v3

물리 폴더 `projects-v1/`는 저장소 배치 이름이고 manifest 버전은 별도다. 옛 입력은 v1, 기존 V4.5 binding 기록은 최소 v2, 품질/UC 필드 또는 V5 binding 기록은 v3다. 현재 reader는 세 버전을 함께 읽는다. 기존 입력/결과는 자동으로 바꾸지 않으며 새 선택/결과를 저장할 때 필요한 버전으로 올린다. 이전 앱은 모르는 버전에서 PROJECT_VERSION으로 멈춘다. 직전 manifest는 불변 내용 해시 이력에 남고 별도 UUID로 복구할 수 있다.

| 결과 기록 | 의미 |
| --- | --- |
| model/sampler/noiseSchedule, seed | 실제 요청에 넣은 식별값/시드 |
| draft/sceneId | 요청 준비 당시 입력·논리 편집 초안. `square`만으로 물리 픽셀을 추론하지 않음 |
| binding.id | `nai-v45-basic512-v1` 또는 `nai-v5-full-v1`: 모델별 필드/직렬화 규칙을 식별. 의미를 유지하고 바꿀 때 새 식별/형식 호환을 결정 |
| binding.requestHash | 인증 헤더를 제외한 실제 전송 JSON UTF-8 바이트의 SHA-256. 현재 고정 바인딩·draft·기록 seed로 요청을 재구성해 대조할 근거 |
| sha256/pngBytes | 재인코딩하지 않은 저장 PNG 원본의 해시/크기 |

v2/v3는 binding의 허용 키/id/해시와 필요한 최소 manifest 버전을 검사한다. v1 파일에 새 키를 몰래 추가하지 않는다. copy/recover는 binding과 PNG 바이트를 함께 보존하고 입력만 저장은 명시적으로 이미지 기록을 제외한다. hash는 서버의 해석·화질·과금을 증명하거나 사용자 파일의 악의적 변경을 인증하는 서명이 아니다. 요청 재생 UI·PNG 메타데이터 의미 추출은 아직 없다.

## 로컬 진단과 화면 경계

첫 운영 응답의 정제 MIME/state·HTTP 상태·진단 버전만 포크 프로필의 `nai-diagnostics/first-response.v1.json`에 best effort로 쓴다. private 폴더/0600·wx, 링크/소유자/권한 검사, 원시 헤더/본문·프롬프트·토큰 없음, 기존 파일 덮어쓰기 없음이다. 실패해도 전송 결과/재시도 여부를 바꾸지 않는다. 정제된 임의 문자열의 비민감성을 수학적으로 증명하는 것은 아니다. **실제 NovelAI의 정확한 MIME은 여전히 미확인**이며 테스트의 binary/octet-stream은 루프백 합성 헤더다.

프로젝트 I/O는 worker의 고정 작업으로 확장하고 PNG add는 메인에서만 호출한다. 새 generation IPC는 현재 승인된 최상위 문서 검사 뒤 prepare/run/status/cancel/retrySave/discard/image만 제공한다. 이미지 읽기는 UUID 프로젝트의 manifest에 실제로 참조된 image UUID에 한하며 임의 경로·PNG 입력은 받지 않는다. 로컬 PNG 읽기는 오프라인에서도 가능하다. D-042의 worker image는 manifest와 선택된 PNG 한 장만 검사한다. 결과 메타데이터는 기존 ProjectSnapshot을 사용하며 리비전 갱신 때 projects.open을 재호출하지 않는다. 열어 둔 동안 관련 없는 PNG가 외부에서 없어져도 선택/준비가 전체 무결성을 보장하지 않으며, 다음 명시적 open은 이를 거부한다. App은 현재 입력/씬·dirty 상태를 계속 소유하고 결과 저장은 그 입력을 임의로 덮어쓰지 않는다.

D-043에서 기본 바인딩의 선택 씬·반복 큐와 묶음 단위 확인/중지/결과-only 최신 manifest append를 연결했다. [대기열 정책](WORKSPACE_QUEUE.md)을 따르며 프롬프트 조각의 실행별 전개·영속 큐는 미구현이다. 기존 단일 run의 기대 리비전 정책은 유지하고 큐는 같은 execute를 호출한다. 기존 mock 큐와 V3 생성은 그대로이며 새 기본1장 경로에 자동 연결하지 않는다. Windows/macOS 전체 앱·실제 계정에서 이 새 UI로의 생성은 미검증이다. [합성 검증](validation/2026-11-22-workspace-generation.md).


## V5 선택과 manifest v3 (D-048)

V5의 품질/부정 프리셋 필드나 nai-v5-full-v1 결과를 저장하면 v3로 기록한다. 현재 앱은 v1/v2/v3를 읽지만 이전 앱은 v3를 열지 못한다. 직전 v1/v2 manifest 이력과 원본 PNG를 보존하며 복구는 새 복사본으로 한다. 기존 V4.5 요청 바이트/고정0 의미와 결과-only 저장 복구는 유지한다.


D-049: 28스텝 이하 단일 생성은 버튼 한 번을 유지한다. 초과 단일 요청은 저장/준비 뒤 모델·크기·스텝·시드와 Anlas 사용 가능성을 한 번 확인하고 전송한다. 취소하면 전송하지 않고 설정으로 돌아간다. 반복 큐는 기존 총 건수/서로 다른 설정 확인 안에 초과 경고만 표시하며 이미지마다 묻지 않는다. 조건 이하를 무료로 계산/보증하지 않는다. 설정 파일이 없는 기존 일반 프로필도 온라인 기본값이 적용되고 저장된 오프라인 선택은 유지한다.

## V5 캐릭터 자동 배치 (D-054)

V5에서 캐릭터 패널의 긍정/부정·켜기/끄기·순서를 편집할 수 있다. 활성22명 이하·자동 배치만 전송하고 기존 무캐릭터 경로는 유지한다. 비활성 입력은 삭제하지 않는다. 같은 단일/큐/취소/저장-only 복구를 사용하고 새 결과는 v4/별도 binding이다. [근거·제한](V5_CHARACTERS.md). 이력·PNG 보존 확인과 실계정 서버 수용/배치 품질은 구분한다.
