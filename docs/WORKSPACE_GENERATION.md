# 새 작업실의 기본 1장 생성 (D-041)

현재 범위는 **데스크톱의 저장된 현재 씬 1장 생성 → 원본 PNG 보관 → 다시 열어 표시**다. V3 로그인/파일을 이관하거나 mock 대기열을 실제 API로 바꾸지 않는다. 기본 실행의 오프라인 정책은 그대로다.

## 사용 흐름

1. 기존 화면 상단의 **새 작업실**을 연다. mock 실행은 기존 오프라인 예제 화면을 유지한다.
2. 실제 생성은 일반 포크 프로필의 **API 토큰·연결 모드**에서 온라인을 저장하고 재시작한 뒤, 사용자가 Persistent API Token을 직접 입력한다. 토큰은 채팅·CLI·환경변수로 받지 않는다. 예전 V3 로그인/TOKEN.txt와는 별도다.
3. 씬을 선택하고 기본/부정 프롬프트·시드 방식을 편집한다. **입력 저장 후 1장 생성 확인**은 먼저 입력을 명시적으로 저장하고 고정 요청을 준비한다. 이 단계에는 네트워크 호출이 없다.
4. 요청 크기·설정·확정 시드 및 저장 형식 변경을 확인한다. NovelAI 웹에서 같은 설정의 비용/사용 조건을 확인한 뒤 **이번 요청 1회 전송**을 누른다. 앱은 무료 여부·Anlas·Opus 할당량을 계산하거나 서버 과금 상한을 강제하지 않는다.
5. 응답 ZIP/PNG 검증 후 원본 PNG와 기록을 프로젝트에 저장한다. 다른 PID에서 같은 프로젝트를 열거나 오프라인으로 실행해도 PNG를 볼 수 있다.

현재는 V4.5 Full 기본 요청에 한정한다. 모델 `nai-diffusion-4-5-full`, action=generate, params_version=3, 512×512, 28스텝, scale=5, n_samples=1, k_euler_ancestral/karras, cfg_rescale=0이다. 캐릭터 조건은 비어 있고 use_coords=false/use_order=true다. 이는 기존 사용자 기본1장 실측의 요청과 같은 고정 바인딩이며, 공식 모델 enum/모든 파라미터 의미·모든 입력 조합을 확인했다는 뜻이 아니다. 서버가 seed0을 어떤 의미로 해석하는지도 새로 확인하지 않았다. 기록의 시드는 **전송한 값**이다.

V5·활성 캐릭터·다른 비율/스텝/가이던스·`|`·`<모음.조각>` 전개는 이번 경로에서 거부한다. 기존 프로젝트의 해당 설정은 읽고 저장할 수 있으며, **기본 설정으로 전환**을 누를 때만 현재 씬의 형식/비율/스텝/가이던스를 바꾸고 캐릭터를 삭제하지 않고 비활성화한다. 이 화면에는 캐릭터 편집/와일드카드·반복 대기열 실행을 붙이지 않았다.

## 실행과 실패

메인은 저장된 UUID/리비전/씬 ID로 요청을 만든다. prepare 전에 오프라인을 거부하고, prepare/run에서 PNG·manifest/리비전·남은 잠금·이력/이미지/JSON 한도를 검사한다. 최대 PNG32 MiB를 보수적으로 예약해 공간을 확인하므로 실제 작은 이미지보다 일찍 보관 한도에 걸릴 수 있다. 파일 권한·디스크·다른 프로세스의 후속 변경까지 보장하는 예약 잠금은 아니다.

무작위 시드는 메인 crypto에서 준비 시 한 번 결정해 확인창에 표시하고 그대로 전송/기록한다. 고정0도 보존한다. 확인은 5분 만료·1회 사용이며 새 prepare/취소로 이전 확인을 폐기한다. run은 첫 await 전에 확인을 선점한다. 리비전이 바뀌면 보내지 않는다. 프로세스당 한 요청/미저장 결과만 허용하며 자동 재시도는 없다. 네트워크/해제 기한은 기존 sendImage의90초이고 저장 worker I/O까지의 전체 작업 기한이라는 뜻은 아니다.

생성은 defaultSession에 묶인 기존 Electron 전송기만 사용한다. 토큰은 메인에서 읽고 렌더러/worker로 보내지 않는다. 쿠키/리다이렉트/오프라인 차단·ZIP/PNG 제한·원본 바이트 보존은 유지한다. 취소·시간 초과·수신/검증/저장 실패는 `mayHaveReachedServer`를 보존해 서버가 처리했거나 사용량이 소모됐을 가능성을 안내한다. 401/402/429는 고정 안내를 사용하고 서버 본문·OS 예외·내부 응답 사유는 화면으로 보내지 않는다.

PNG 수신 뒤 저장만 실패하면 최대32 MiB 원본을 메인 메모리에1건 유지한다. **결과만 다시 저장**은 최신 manifest를 다시 읽고 같은 결과 UUID가 이미 기록돼 있으면 PNG 해시를 확인해 중복 추가하지 않는다. **입력·이번 결과만 새 프로젝트로 저장**은 준비 당시 입력/씬과 이번 PNG만 새 UUID에 저장하며 이전 PNG·원본 잠금/파일은 건드리지 않는다. 원래 프로젝트의 이미지까지 복구했다고 표시하지 않는다. worker 중지라면 이 영역에서 저장 기능을 명시적으로 다시 시작한 뒤 저장을 별도로 고른다. 미저장 PNG를 버리려면 별도 선택을 확인한다.

메모리 결과는 프로세스 종료/재시작 뒤 복구할 수 있는 내구성 저장이 아니다. 저장 실패 때 창을 강제 종료하지 않는다. UI의 busy 상태 외에도 메인의 정상 finish/연결 모드 재시작이 진행 요청·미저장 PNG를 확인해 거부한다. renderer crash/unresponsive의 native dialog에서 명시적으로 버리고 닫는 선택은 유지하며 메모리 PNG 손실 가능성도 안내한다.

## 저장 형식 v1/v2

물리 폴더 `projects-v1/`는 저장소 배치 이름이고 manifest 버전은 별도다. 입력만 있는 프로젝트는 v1로 만들며 기존 v1을 계속 읽는다. 새 생성 결과에는 아래 메타데이터를 추가하고 **그 명시적 결과 저장 때만** manifest를 v2로 쓴다. v1만 읽는 이전 앱은 v2에 PROJECT_VERSION으로 멈추며 잘못 덮어쓰지 않는다. 확인창에 이 차이를 표시한다. 직전 v1 manifest는 기존 내용 해시 이력에 남고 별도 UUID로 복구할 수 있다.

| 결과 기록 | 의미 |
| --- | --- |
| model/sampler/noiseSchedule, seed | 실제 요청에 넣은 식별값/시드 |
| draft/sceneId | 요청 준비 당시 입력·논리 편집 초안. `square`만으로 물리 픽셀을 추론하지 않음 |
| binding.id | `nai-v45-basic512-v1`: 위 고정 필드/직렬화 규칙을 식별. 의미를 유지하고 바꿀 때 새 식별/형식 호환을 결정 |
| binding.requestHash | 인증 헤더를 제외한 실제 전송 JSON UTF-8 바이트의 SHA-256. 현재 고정 바인딩·draft·기록 seed로 요청을 재구성해 대조할 근거 |
| sha256/pngBytes | 재인코딩하지 않은 저장 PNG 원본의 해시/크기 |

v2는 binding의 허용 키/id/해시를 좁게 검사한다. v1 파일에 새 키를 몰래 추가하지 않는다. copy/recover는 binding과 PNG 바이트를 함께 보존하고 입력만 저장은 명시적으로 이미지 기록을 제외한다. hash는 서버의 해석·화질·과금을 증명하거나 사용자 파일의 악의적 변경을 인증하는 서명이 아니다. 요청 재생 UI·PNG 메타데이터 의미 추출은 아직 없다.

## 로컬 진단과 화면 경계

첫 운영 응답의 정제 MIME/state·HTTP 상태·진단 버전만 포크 프로필의 `nai-diagnostics/first-response.v1.json`에 best effort로 쓴다. private 폴더/0600·wx, 링크/소유자/권한 검사, 원시 헤더/본문·프롬프트·토큰 없음, 기존 파일 덮어쓰기 없음이다. 실패해도 전송 결과/재시도 여부를 바꾸지 않는다. 정제된 임의 문자열의 비민감성을 수학적으로 증명하는 것은 아니다. **실제 NovelAI의 정확한 MIME은 여전히 미확인**이며 테스트의 binary/octet-stream은 루프백 합성 헤더다.

프로젝트 I/O는 worker의 고정 작업으로 확장하고 PNG add는 메인에서만 호출한다. 새 generation IPC는 현재 승인된 최상위 문서 검사 뒤 prepare/run/status/cancel/retrySave/discard/image만 제공한다. 이미지 읽기는 UUID 프로젝트의 manifest에 실제로 참조된 image UUID에 한하며 임의 경로·PNG 입력은 받지 않는다. 로컬 PNG 읽기는 오프라인에서도 가능하다. App은 현재 입력/씬·dirty 상태를 계속 소유하고 결과 저장은 그 입력을 임의로 덮어쓰지 않는다.

연속 예약/선택 씬 여러 개·프롬프트 조각의 실행별 전개·비용 확인 단위/취소·영속 큐는 다음 P1-02b다. 기존 mock 큐와 V3 생성은 그대로이며 새 기본1장 경로에 자동 연결하지 않는다. Windows/macOS 전체 앱·실제 계정에서 이 새 UI로의 생성은 미검증이다. [합성 검증](validation/2026-11-22-workspace-generation.md).
