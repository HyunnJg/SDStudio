## 이번에 확인한 사실

- 기존 장점: 씬별 예약 생성, 이미지 선별, 인페인팅, 프롬프트 조각과 조합. 원본 README와 해당 소스가 존재한다. 현재 환경에서 기능 작동을 검증한 것은 아니다.
- `src/renderer/backends/genVendors/nai.ts`는 `nai-diffusion-3` 계열을 매핑한다. 공식 V4.5/V5 입력 구조는 별도 초안으로 조사했고 실제 모델 바인딩은 P0-03b다.
- 고정 원본 f2088 트리에는 독립 LICENSE가 없지만 조상 7091c91에서 ERB MIT 원문을 발견해 LICENSES/electron-react-boilerplate.txt에 보존한다. 앱 고유 저작권 문구는 미확인이다. 루트/배포 패키지는 MIT, 네이티브는 ISC로 표기한다. [확인 범위](LICENSE_REVIEW.md)를 참고한다.
- 원본 IP 확인은 온라인 모바일 분기에만 남겼다. 데스크톱에서는 호출·UUID 저장을 하지 않는다. 업데이트는 기본 비활성이고 포크를 참조한다.
- 업데이트 생성자의 자동 시작을 제거하고 중복 run과 stop을 테스트했다. 오프라인 로컬 AI와 계정/API·다운로드는 실행 전에 거부한다.
- 격리 프로필에서는 원본 userData 조회 부작용도 피하며 saveLocation을 무시한다. 원본 커스텀 저장 폴더는 자동 탐지하지 않으므로 그 안에 개발 프로필을 만들지 않는다.
- `<모음.조각>`과 `multi` 랜덤 선택은 이미 구현돼 있다. 선택은 `Math.random()`을 사용한다. P2-01을 새 기능이 아닌 재현성·기록 개선으로 수정했다.
- 원본 CI에는 다중 OS 패키징, 서명, 릴리스 및 Pages 배포 구성이 있다. 이 포크에서 활성화하거나 실행하지 않았다.

## Windows 설치 문의 후속 — 2026-11-22

사용자 로그에서 로컬 @electron/node-gyp10.2.0-electron.1의 VS2026 인식 실패를 확인했다. 이후 Node installer는 정상 원본/Win64 설정인데 dist/locales만 남았고 이유는 미확정이다. 공식 ZIP의 SHA-256 검증 후 PowerShell 해제를 안내했고 사용자가 GUI/실제 API 응답을 보고했다. [Windows 복구](../tools/nai-validation/WINDOWS.md). 실험 도구는 **tools/nai-validation 독립 설치**로 앱 C++ 빌드를 거치지 않게 분리했다. Linux의 루트 node_modules 없는 임시 체크아웃에서 실제 창/오프라인 차단을 검증했고 기존 연구 창5경로도 통과했다. Windows 전체 앱 npm install·Node26/VS2026 호환 완료는 아니다. [새 명령](DEVELOPMENT.md#1회-실호출-검증-도구-d-032), [검증](validation/2026-11-22-standalone-validation.md).
