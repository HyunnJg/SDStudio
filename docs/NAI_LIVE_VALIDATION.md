# 실제 생성 검증 — 기본1장 실측 완료

2026-11-22 (Asia/Seoul). **기본1장 실측2회는 완료했다.** 첫 요청은 MIME거부로ZIP이잘렸고, 두 번째는 같은 요청으로 전체ZIP/PNG검사·원본저장에 성공했다. [성공/한계](validation/2026-11-22-live-success.md). 사용자계정의 Anlas관찰차이는0이고 할당량 전후수치는 미측정이다. 개발 환경은 실제 토큰/계정 호출을 하지 않았다. 아래는 이미 완료한 실험의 실행/보관 절차이며 다음 호출을 요청하는 지시가 아니다.

## 이번 경로

일반 앱의 작업실/대기열이 아니라 개발 체크아웃의 **별도 Electron 실험 창**을 사용한다. 창만 필요하면 tools/nai-validation을 독립 설치하며 루트 npm install/C++ 빌드는 필요 없다. 기존 토큰·프로젝트를 검색하거나 가져오지 않는다. 실제 Persistent API Token은 사용자가 자기 PC의 이 창에 직접 입력한다. 채팅·CLI 인자·환경변수·Git에 넣지 않는다. 이번 실행의 메모리에만 보관하며 전송 시도 후 또는 창 종료 시 사본을 버린다. Account ID나 계정 비밀번호는 인증 토큰이 아니다.

[실행 안내](DEVELOPMENT.md#1회-실호출-검증-도구-d-032), [합성 검증](validation/2026-11-21-live-validation.md), 결정 D-032를 함께 읽는다. 개발 환경은 사용자의 실제 토큰을 받지 않았으며 합성 루프백만 실행했다. 사용자 제공 정제 관찰과 로컬 자동 검증을 구분한다.

## 고정 후보와 확인 범위

`.erb/fixtures/nai-live-candidate.json`은 **unverified-experimental-candidate**다. 운영 모델 목록이나 UI 기본값으로 쓰지 않는다. 공식 [Image API 스키마](https://image.novelai.net/docs/doc.json)의 model은 string이며 모델 ID enum·모델별 기본값은 확인되지 않았다. 아래 값은 서버 수락 여부를 실험할 가설이다. 비공식 구현의 문자열을 공식 확인 사실로 승격하지 않는다.

| 크기 / steps / scale | 512×512 / 28 / 5 |

캐릭터·격자·참조 입력, V5, 새 프로젝트 저장 호환은 이번 단일 기본 요청이 성공해도 검증되지 않는다. ZIP flags/method/extra 길이는 숫자만 기록한다. 현재 좁은 ZIP/PNG 프로필과의 호환도 실제 응답에서 확인해야 한다.

## 비용 확인과 실행 순서

1. 다른 창/대기열의 생성을 멈추고 테스트 프로필을 저장소 및 원본/포크 기본 프로필 밖에 고른다. 정상 앱의 온라인 설정을 바꾸는 실험이 아니다.
2. 실험 창의 고정 JSON을 펼쳐 확인한다. NovelAI 웹에서 **동일한 모델·해상도·스텝·샘플러·부가 설정**의 표시 비용과 현재 잔액을 직접 확인한다. 웹에서 실제로 생성할 필요는 없다. 동일 설정의 비용을 확인할 수 없다면 전송하지 않는다.
3. 창에 실행 전 잔액과 웹 표시 비용을 입력한다. 같은 설정 확인·비공개 원문 보관·미확인 후보라는 세 항목을 직접 선택한다. 입력값과 고정 요청 SHA-256을 묶어 기록한다. 구독 이름이나 해상도만으로 무료라고 추정하지 않는다.
4. 표시 비용 0~10, 잔액 충분, 토큰 로컬 읽기, 강제 오프라인 없음, 기록 파일 생성이 모두 통과한 뒤에만 **실제 API 1회 전송**을 누른다. 키가 맞는지 확인하는 별도 계정 API는 호출하지 않는다.
5. 응답/오류 뒤 웹 잔액을 다시 확인해 실행 후 잔액을 기록한다. 실행 전 잔액·표시 비용은 attempt.json, 실행 후 잔액·관찰 차이는 balance-after.json에 각각 남는다. 잔액 차이는 다른 활동·갱신 지연의 영향을 받을 수 있어 이 요청의 과금 증명이 아니다.
6. 실패·취소·기한 초과·서버 형식 불일치 때 자동 재시도하지 않는다. 같은 프로필의 두 번째 전송도 막힌다. 결과와 서버 처리 가능성을 먼저 검토한다. 재호출을 위해 기록을 지우거나 새 프로필을 자동 생성하지 않는다.

비용 입력은 **사용자의 웹 확인 진술**이다. 앱은 서버 가격을 독립 계산하거나 실제 청구를 제한하지 않는다. 위임된 최초 범위를 이 구분 없이 “10 Anlas 강제 과금 한도”로 설명하지 않는다.

## 비공개 응답 보관과 재검사

실험 실행 및 보관 선택 전에는 응답을 수집하지 않는다. 실험 경로만 `diagnosticCapture`를 명시적으로 켠다. 일반 앱의 전송기는 여전히 오류 본문을 폐기한다. 받은 이미지 응답은 최대 64 MiB이고 **해제/검증 전에** 선택한 프로필의 live-validation/response.zip에 원본 그대로 보관한다. 비2xx 또는 ZIP시작부가 없는2xx MIME 불일치의 오류 본문은 최대64KiB만 보관하고 잘렸으면 captureTruncated=true를 기록한다. 이때 확장자가zip이어도 실제 내용은JSON/텍스트일 수 있다. D-034 이후 연구 경로는 미분류 MIME의2xx도 PK0304 시작부가 있으면 전체64MiB상한으로 받고 기존 ZIP/PNG 검사를 적용한다. HTML/오류 본문이나 ZIP시작부만으로 성공 처리하지 않는다.

| 로컬 파일 | 내용 |
| --- | --- |
| attempt.json | 요청 해시·시각·수동 확인 비용/실행 전 잔액·1회 계획 |
| response.zip | 비공개 응답 원문. 이미지/프롬프트 metadata 또는 서버 오류 내용이 있을 수 있음 |
| result.json | 허용된 오류 코드·고정 사유·HTTP 상태·분류 MIME·바이트 수·서버 처리 가능성 |
| result.png | 검증 성공 때만 원본 PNG. 재인코딩하지 않음 |
| balance-after.json | 수동 실행 후 잔액과 관찰 차이. 결과 파일 없는 재개는 incomplete=true/resultRecord=missing. 덮어쓰기 없음 |

Linux에서 보관 디렉터리 0700/동일 소유자·링크 거부, 파일 wx/0600을 확인했다. attempt/응답/JSON은 fsync하며 기존 파일은 덮어쓰지 않는다. Windows ACL과 macOS 실기는 미검증이다. 선택한 폴더는 사용자가 비공개로 관리한다. 원문 파일/PNG·개인 경로·계정/토큰을 PR이나 공유 로그에 올리지 않는다.

전송 전에 attempt.json을 선점하므로 실패/충돌/프로세스 재시작도 추가 요청을 자동 허용하지 않는다. 이 파일이 남았다는 사실이 전송이나 과금을 증명하지는 않는다. 응답 전 취소·네트워크 단절이면 빈 response.zip 예약 파일만 남을 수 있고 **responseCaptured=false**다. 수신 상한 초과·중간 연결 단절에도 완전한 응답 보관을 보장하지 않는다. 보관 실패는 RESPONSE_CAPTURE_FAILED이며 다시 보내지 않는다.

```sh
npm run nai:inspect-response -- /absolute/test-profile/live-validation/response.zip
```

responseCaptured=true인 파일을 로컬에서 재검사한다. HTTP 오류 본문이면 ZIP 검사에서 거부되는 것이 정상이다. 도구는 API/토큰 없이 파일 하나를 읽고 고정 코드·사유·바이트 수만 출력한다. 과거 서버 처리/과금을 판정하지 않는다. 불량 ZIP 합성 테스트에서 보관 파일과 재검사 사유 zip-eocd가 같음을 실제 Electron 창에서 확인했다.


## 첫 관찰과 수정 후 추가1회 규칙 (D-034)

[첫 정제 관찰](validation/2026-11-22-first-live-observation.json)은 HTTP200·contentType=other·ZIP시작부·responseBytes=65536·captureTruncated=true다. 실제 MIME 문자열은 보존되지 않았고 전체 PNG도 없다. 이 파일을 복구하거나 생성 성공으로 표시하지 않는다. 기존 프로필의 attempt/response/result/잔액 기록은 그대로 보존한다. 신규 결과에는 acceptedByZipSignature와 elapsedMs가 추가된다.

추가 실험은 **이번 MIME 수신 보완 후 동일한 요청 해시로1회만**이다. 전체 시도는2회까지이며 자동 실행하지 않는다. 첫 프로필 attempt.json의 displayedCost를 로컬에서 확인하고 새 웹 표시 비용과의 합계가10 Anlas 이하여야 한다. 잔액 차이0만으로 첫 비용을0으로 대신 입력하지 않는다. 값을 확인할 수 없으면 전송하지 않는다. 새 실험 창에서도 동일 설정의 비용·현재 잔액 확인을 반복한다. 이 합계도 수동 확인 기준이며 서버 강제 청구 상한이 아니다.

기존 창을 닫고 업데이트한 work/p0-live-recovery 브랜치에서 SDStudio-Live-Test-02 같은 새 명시적 프로필을 선택한다. 이미 복구한 Electron을 유지하려면 의존성 변경이 없는 이번 업데이트에 npm ci를 다시 실행할 필요가 없다. 요청 JSON·seed0·해시는 그대로다. 후속이 또 실패하면 보관된 원문을 먼저 로컬 재검사하고 추가 호출은 재검토한다. HTTP400도 무료라고 단정하지 않는다.

결과 파일 없이 재개한 프로필에서는 모든 이전 실행 창이 종료됐는지 먼저 확인하고 웹 잔액만 기록할 수 있다. incomplete는 결과 기록 부재이며 서버 작업/과금 상태를 뜻하지 않는다. 현재 인스턴스에서 요청이 진행 중이면 기록 버튼/IPC는 거부한다. 기록 복구는 토큰·네트워크를 사용하거나 재전송하지 않는다.


## Opus와 실측 종료 (D-035)

사용자가 Opus임을 설명했고 두 번째 결과는 ok=true/PNG609129바이트/원본저장, Anlas잔액 관찰차이0이다. 할당량을 소모했다는 설명과 실제 할당량 전후미측정을 구분한다. 공식 [구독 문서](https://docs.novelai.net/en/subscription/)는 조건부무료와 V4.5초과의usage limit을 구분하므로 이번 V4.5후보의 할당량 감소를 추정하지 않는다. 이 도구는 Anlas비용/잔액만 기록하며 사용량·할당량이0소모됐다는 뜻은 아니다. 웹에서 실제 무료표시를 확인했을 때 비용0 입력은 허용된다.

두 번의 실측은 끝났다. 이미 사용한 프로필/원문/PNG를 보존하고 재전송을 위해 초기화하지 않는다. 다음 저장/복구 구현은 합성 데이터로 진행한다. 원본 이미지나 토큰을 공유할 필요가 없다.

## PR #16 후속 진단 형식 (D-036)

이 절은 추가 실험 지시가 아니다. 완료한 두 번의 실측 기록은 변경하지 않는다. 새 연구 결과에는 `mediaTypeState: present | absent | invalid`가 추가되며 present일 때만 길이/형식 검사와 파라미터 제거를 거친 `mediaType`을 기록한다. `contentType` 분류에도 absent/invalid가 추가된다. 실제 서버의 과거 문자열은 여전히 미확인이고 테스트 MIME 문자열은 합성 값이다. 원시 헤더나 그 파라미터는 기록하지 않는다.

운영 `sendImage()`도 진단 보관 없이 2xx ZIP 시작부와 엄격 해석으로 수신할 수 있지만, 연구 `send()`는 해석 전 원문 보관을 위한 명시적 옵션을 유지한다. 연구 실행 상태는 예기치 못한 후처리 예외에도 finally에서 해제하고, 사용한 attempt 기록·재전송 거부는 유지한다. [검증](validation/2026-11-22-production-image-transport.md).
