# 결정 기록

날짜: 2026-11-20

## D-001 — SDStudio를 기반으로 한다 (확정)

- 사용자 방향: SDStudio만 포킹한다.
- 이유: 씬별 생성 예약 → 이미지 선별 → 리터칭 흐름을 활용할 수 있다.
- 적용: 원본 이력을 유지한 포크를 사용하고, 다른 프로그램을 통째로 결합하지 않는다.

## D-002 — NovelAI와 익숙한 사용 흐름을 만든다 (방향 확정, 상세 설계 미정)

- 사용자 방향: NovelAI 홈페이지와 비슷한 UI를 희망한다.
- 구현 원칙: 프롬프트, 설정, 생성 결과와 대기열에 쉽게 접근하도록 자체 UI를 구성한다.
- 아직 결정하지 않은 것: 정확한 패널 위치, 테마, 단축키, 지원 모델.

## D-003 — 다른 오픈소스의 장점은 선별 도입한다 (확정)

- 사용자 방향: 사용 가능한 라이선스의 프로젝트에서 장점을 취합한다.
- 적용: 출처·리비전·라이선스·도입 범위를 조사한 뒤 선택한다.
- `NAI-Auto-Generator`는 현재 조사 범위에서 독립된 라이선스 파일을 찾지 못했다. 이번 작업에서는 코드나 자산을 가져오지 않았다.
- `<모음.조각>`과 `multi` 랜덤 조각은 기존 구현이다. 신규 와일드카드 문법보다 재현성·최종 프롬프트 기록 개선을 먼저 검토한다. 폴더 순회는 기능 후보다.

## D-004 — GitHub를 공용 인수인계 지점으로 사용한다 (확정)

- 사용자 방향: 다른 AI들과 진도를 함께 검토할 GitHub 작업공간을 만든다.
- 적용: 이 포크의 코드·현재 상태·결정·검토 기록을 공용 기준으로 삼는다.
- 협업 규칙: 실제 커밋을 기준으로 검토하고, 작업별 브랜치와 PR로 변경을 추적한다. 검토 역할은 모델 회사에 고정하지 않는다.

## D-005 — 먼저 기존 동작을 재현하고 화면을 단계적으로 바꾼다 (검토 반영)

- 이유: 기존 모델 매핑, 네이티브 빌드, 저장 데이터와 외부 요청을 확인해야 화면 개편 후의 회귀를 구분할 수 있다.
- 순서: 원본 데이터 경로 격리·실행 시 외부 요청 통제 → 데스크톱 실행 기준 → 모델/API 조사와 지원 범위 결정 → P1 새 화면 → P2 반복 작업 개선 → P3 배포 정리.
- 설치·빌드는 앱 기동과 구분한다. 원본 프로필에 접근하지 않는 조건과 외부 요청 통제를 마련하기 전에 앱을 실행하지 않는다.
- 근거: 사용자 제공 Gemini·Claude 검토를 소스와 대조했다. [처리 결과](reviews/2026-11-20-review-resolution.md)에 채택 범위와 미검증 주장을 기록했다.

## D-006 — 첫 재현 범위는 Electron 데스크톱으로 한정한다 (검토 반영)

- Android/iOS 패키징과 Python/BiRefNet 빌드를 첫 성공 조건에서 제외한다. 최종 지원 OS 정책은 별도다.
- 단, 루트의 `file:externals/capacitor-background-mode` 의존성처럼 데스크톱 설치에도 필요한 모듈은 실측 후 처리한다. 서브모듈을 일괄 삭제하지 않는다.
- Node `22.4.1`은 원본 CI 재현 기준이다. 현재 권장·지원 버전이라는 의미가 아니다. 성공한 의존성 조합의 lock 파일 추적과 깨끗한 체크아웃의 `npm ci` 재현을 완료 조건으로 한다.

## D-007 — 외부 요청과 데이터 경로를 먼저 분리한다 (데스크톱 구현·오프라인 검증 완료)

- `main.ts`의 모듈 최상위 `DEFAULT_APP_DIR`가 평가되기 전에 개발 전용의 빈 데이터 경로를 선택한다. `whenReady()` 또는 `init()`에서 뒤늦게 바꾸지 않는다. `config.saveLocation`으로 원본 경로가 다시 선택되지 않는지도 확인한다.
- 데스크톱에서 결과를 쓰지 않는 원본 IP 확인 호출을 제거한다. 모바일 동작 변경은 별도 결정으로 남긴다. 기존 IP 확인에는 요청 타임아웃도 없어 존치 여부 검토에 포함한다.
- 업데이트 중복 시작을 제거하고 개발·가짜 백엔드 모드에서는 업데이트·로컬 AI 실행 및 다운로드를 끈다. 가짜 백엔드 실행의 외부 요청 0건을 검증한다.
- 모델 전체 의존성 주입 구조로 크게 재작성하기보다 기존 선택 지점과 시작 경로부터 작게 바꾼다.
- 첫 구현: `SDSTUDIO_USER_DATA_DIR`가 있을 때 초기 import에서 Electron 저장 경로를 선택하고 `saveLocation`을 무시한다. `profile:check`는 앱 초기화 전 종료한다. [Linux 검증과 한계](validation/2026-11-20-p0-profile.md)를 기록했다.

## D-008 — 모델 조사와 저장 형식 설계를 UI보다 앞에 둔다 (검토 반영)

- P0-03을 P1-01의 선행 조건으로 추가한다. 공식 근거·확인 날짜와 지원 범위, 기존 씬 호환 경로를 기록한 뒤 화면 입력 항목을 결정한다.
- 리뷰의 최신 모델 ID·인증·Vibe/참조·캐릭터 필드 설명은 조사 단서다. 현행 규격으로 확정하지 않는다.
- P0-03의 조사·설계와 실제 API 구현, 저장 마이그레이션은 구분한다. 저장 형식 변경은 별도 PR로 검증한다.

## D-009 — 오프라인 예제와 실제 계정 실행을 구분한다 (구현·검증)

- 격리 프로필은 기본 오프라인이며 명시적인 SDSTUDIO_OFFLINE=0이 있어야 온라인을 선택한다. 가짜 백엔드는 항상 오프라인이다.
- 가짜 백엔드의 데이터는 메모리에만 있고 결과는 PNG 픽스처다. 예제 화면에 실제 생성/저장이 없음을 표시한다. Electron 가짜 모드는 격리 경로 없이는 시작하지 않는다.
- 네트워크·로컬 AI·업데이트를 시작 지점에서 제어하고 단위 검사와 실제 창 기동을 함께 확인한다. 테스트 하네스의 단일 인스턴스 잠금 모의와 실기 한계는 결과에 표시한다.


## D-010 — 초기화 실패를 표시하고 프로세스를 종료한다 (PR #3 추가 검토 반영)

- ready 이후 init을 호출해 즉시 오류 처리 경로에 연결하고, init 및 첫 창 생성 실패는 로그와 오류 대화상자에 보고한 뒤 종료 코드 1로 종료한다. 창 없이 실행만 남는 상태를 피한다.
- 개발용 preload·data 경로는 비패키징 development 실행에만 쓴다. DEBUG_PROD는 디버그 기능 선택이며 배포 파일 위치를 바꾸지 않는다.
- 업데이트 알림은 현재 릴리스에서도 꺼져 있다. P3에서 활성화 여부를 결정하며 enabled일 때 버전 조회 함수가 필수인 타입으로 제한한다.

## D-011 — 원격 폰트 대신 시스템 폴백을 사용한다 (제품 동작 명시)

- PR #3의 Google Fonts import 제거는 온라인을 포함한 모든 빌드에 적용된다. OS별 한글 글꼴이 달라질 수 있다.
- P1에서 로컬 폰트 번들을 검토하되 assets/fonts의 고지·라이선스를 확인한 뒤 결정한다. 이번 변경에서 폰트를 추가하지 않았다.


## D-012 — 모델 조사와 실제 전송을 두 단계로 나눈다 (P0-03a)

- 공식 자료에서 확인한 입력 구조를 독립 초안으로 만들고 합성 요청·PNG 응답을 검증한다. 모델별 API ID·필수값이 없는 공개 스키마를 완성된 서버 계약으로 취급하지 않는다.
- 첫 신규 연동 목표는 V4.5 Full, V5는 22캐릭터 입력 범위까지 설계에 반영한다. 제품명에서 API ID를 추측해 등록하지 않는다. [근거와 지원 범위](NOVELAI_API.md)를 따른다.
- 기존 V3 세션·로그인·실제 전송은 유지하고 새 초안은 메모리에서만 다룬다. P1-01은 오프라인 화면, P0-03b 이후 P1-02는 실제 연결로 나눈다. P0-03a 완료를 전체 연동 완료라고 표시하지 않는다.


## D-013 — 신규 인증·전송은 메인에서 맡는다 (P0-03b 구현 전 결정)

- 새 토큰을 렌더러로 전달하는 IPC를 만들지 않는다. 메인은 토큰 저장과 새 전송을 담당하고 렌더러는 토큰 없는 입력/결과만 주고받는다. 기존 V3 인증 경로는 이번에 바꾸지 않는다.
- 새 전송은 세션에 명시적으로 묶인 Electron 네트워크 경로를 사용하고, IPC와 전송 함수 양쪽에서 오프라인을 선행 거부한다. Node fetch를 추가해 기존 Chromium 차단 밖으로 나가지 않는다.
- 정확한 API 선택과 session.webRequest 차단 동작은 현재 Electron 버전의 실기 검사 후 확정한다. 이 결정만으로 네트워크/보안 저장이 구현되었다고 표시하지 않는다.
- 최소 실호출은 계정, 요청 수, Anlas 상한, 중지 조건을 정한 별도 요청 범위에서 진행한다. 현재는 계정·비용 한도가 없으므로 호출하지 않는다.

## D-014 — 새 화면에서 V3 자료는 읽기 전용으로 요약한다 (P1-01)

- 새 화면은 mock 모드에서만 제공하는 메모리 초안이다. 기존 V3 프로젝트·씬은 이름/개수만 읽기 전용으로 표시하고 편집은 명시적인 기존 V3 화면 전환으로 제공한다.
- 두 화면 사이를 이동해도 메모리 초안은 유지한다. V3 프롬프트를 새 모델로 자동 복사·분해·저장하지 않는다.
- 캐릭터 위치의 사용자 입력은 격자 행/열을 원본으로 둔다. 정규화 좌표는 예제 요청을 만들 때만 계산하며 실제 모델의 양자화 규칙으로 확정하지 않는다.


## D-015 — 새 작업실은 mock 모드에서 먼저 검토한다 (P1-01)

- 프롬프트·캐릭터 / 결과·예제 기록 / 설정의 세 영역을 쓰고 작은 창은 세로 스크롤과 하단 실행 영역으로 전환한다.
- 비 mock 실행은 기존 화면을 유지한다. 원본 저장 경로·세션 스키마·V3 생성 API를 새 UI의 임시 초안에 맞춰 바꾸지 않는다.
- 예제는 직접 작성한 SVG와 합성 오류를 사용한다. 기본적인 배치·상태·복구 경험을 검토하며 실제 이미지 생성이나 서버 오류 수신을 주장하지 않는다.


## D-016 — 씬·대기열을 실제 연결 전에 mock으로 검토한다 (PR #5 검토 반영)

- P1-01b에서 새 메모리 씬 3개와 반복 2회의 예약·진행·중지·결과 열기를 먼저 구현한다. V3 세션을 변환하거나 저장하지 않는다. 하단 씬·대기열 영역을 두고 편집 영역을 패널별로 분리한다.
- 기본 시드는 무작위, 고정 모드는 0도 보존한다. 무작위 값은 실행 직전에 정하고 실제 사용한 요청과 함께 기록한다. 예약 시 초안을 복사하여 후속 편집과 분리한다.
- 전역 알림·대화상자는 두 화면 공통으로 표시한다. 검증 오류는 영문 문구 대신 코드로 번역한다.
- 새 작업실은 기존 밝게/어둡게 설정을 따른다. 캐릭터 한도는 활성 수로 판정하고 형식 전환 즉시 초과를 표시한다. 전체 보관 슬롯은 32개로 제한하고 삭제 취소를 제공한다.
- 5×5 격자는 예제 정책이며 V4.5/V5의 실제 좌표 규칙은 P0-03b에서 별도 확인한다.


## D-017 — 예제 대기열의 중지·실패·기록 정책 (P1-01b)

- 예약 시 씬별 초안을 복사하고 실행 직전에 무작위 시드를 결정한다. 같은 예약에서 무작위 시드 충돌을 피하며 고정 0은 그대로 반복한다.
- 중지는 현재 예제를 마친 뒤 다음 예약을 시작하지 않는 동작이다. 계속은 남은 대기 작업만 진행한다. 실패 시 자동 중지·전역 안내를 제공하고 실패 작업을 자동 재시도하지 않는다. 재예약은 명시적으로 전체 예약을 교체한다.
- 큐와 결과 수명은 App에 둬 기존 화면을 보더라도 진행·결과가 유지된다. 결과와 실제 요청·씬 이름을 함께 기록한다. 예약 최대 60개, 최근 결과 120개, 실제 파일 저장 없음.
- 마지막 캐릭터 삭제 1건은 현재 씬에서 취소할 수 있다. 시간 제한을 두는 대신 다음 삭제·씬/화면 전환까지 제공한다. 슬롯 32개를 넘기는 복원은 허용하지 않는다.
- 이 구현은 실제 V3 대기열·프리셋·와일드카드와의 연결을 완료한 것이 아니다. 그 연결 및 과금/취소 정책은 P0-03b 이후 P1-02다.

## D-018 — 실제 연결 전 큐 정책·전송 수명을 확정한다 (PR #6 검토 반영)

- P1-02는 반복 우선/씬 우선 순서를 명시적으로 결정한다. mock은 반복 우선이다. 기존 V3는 task.total을 마친 뒤 다음 작업으로 넘어간다.
- V3는 프롬프트 구조를 예약 때 만들고 random 노드 선택은 handleTask의 lowerPromptNode에서 실행한다. '와일드카드는 예약 때 한 번만 결정'으로 단정하지 않는다. 새 경로는 전개 시점과 최종 문자열·시드 기록, 기존 호환 선택을 함께 검증한다.
- 실제 단일 실행도 현재 씬 1건으로 공통 실행기를 사용하는 방향을 검토한다. 선택 씬만 예약도 P1-02에 포함한다. 현재 mock 두 경로를 실 API의 완료된 공통 경로로 표시하지 않는다.

## D-025 — 신규 인증·전송 기반은 실제 생성 연결과 분리해 검증한다 (P0-03b1)

- 메인에 세션 한정/OS 암호화 보관을 구현하고 상태·설정·삭제 IPC만 제공한다. 평문 대체와 새 토큰 반환 IPC는 만들지 않는다. Linux basic_text/unknown은 영구 보관을 거부한다. 기존 V3 TOKEN.txt를 자동 이관하지 않는다.
- 새 IPC는 현재 mainWindow의 승인된 문서·최상위 프레임만 받고 오프라인을 저장소 접근 전에 거부한다. 영구 보관 실패·미지원 버전·복호화 실패는 코드로 전달하고 기존 기록을 자동 삭제하지 않는다.
- 전송기는 defaultSession에 묶인 Electron net.request를 사용한다. 동일 오프라인 훅에서 차단됨을 실측했다. 고정 엔드포인트, 쿠키 배제·리다이렉트 거부, 전체 기한·AbortSignal·write 직전 재확인 및 재시도 금지를 유지한다. write 이후 실패/취소는 서버 처리 여부 불명으로 남긴다.
- 로컬 응답/실제 Electron 실험에서 writable close가 응답보다 먼저 발생해 close 자체로 완료/실패를 판단하지 않는다. 응답·기한 기반으로 판정하고 해당 순서를 회귀로 검증한다.
- 상세 범위·수치 한도는 [인증·전송 기반](NAI_AUTH_TRANSPORT.md). P0-03b1은 인증 입력 UI/유효성 확인, 최신 모델 등록, 저장 마이그레이션과 과금 생성 성공이 아니다. 나머지는 P0-03b2 및 P1-02로 유지한다.

## D-027 — 보관·로컬 읽기·서버 인증을 구분한다 (P0-03b2 인증 UI 부분)

- 새 작업실과 기존 데스크톱 화면에서 같은 토큰 설정창을 연다. 기본은 이번 실행 한정, OS 보안 저장이 불가하면 영구 선택을 비활성화한다. 입력은 패널 DOM에만 두고 App/씬/세션/결과에 저장하지 않는다. 성공/닫기 때 입력을 비우며 실패 시 재입력을 위해 현재 패널에만 유지한다.
- UI가 앞뒤 공백/줄바꿈만 제거하고 안내한다. 중간 공백·개행·길이 검사는 UI와 메인에서 거부한다. 입력을 maxLength로 조용히 잘라 저장하지 않는다.
- 저장됨은 로그인 성공이 아니다. 새 check IPC는 사용자가 누를 때만 read 후 상태/locallyReadable만 반환하며 네트워크 호출이나 토큰 반환이 없다. 기존 발신자·오프라인 거부를 그대로 적용한다.
- 미지원/손상 파일은 읽기 및 교체 실패 때 유지한다. 삭제는 별도 확인으로만 수행하며 로컬 사본 삭제와 서버 토큰 폐기를 구분한다. native dialog의 포커스/Escape/닫기 정리와 좁은 창을 검증한다.
- 실제 모델 전송·계정 검증·ZIP 해제 제한·새 프로젝트 저장은 P0-03b2의 남은 범위다. 미확인 모델 ID를 등록하지 않는다. 실호출 계획에는 실제 MIME, 상태별 사용자 안내(401/402/429 등), 필요한 경우 명시적으로 선택한 길이 제한 로컬 오류 진단을 남기며 운영 원문 오류 폐기는 유지한다.


## D-028 — 일반 포크의 연결 모드는 저장 후 실제 재시작으로 적용한다

- 최초 실행은 오프라인이다. 일반 프로필은 API 토큰 창에서 온라인/오프라인을 다음 시작 값으로 저장한다. 실행 중의 runtimeOptions·요청/토큰 IPC 차단을 즉시 해제하지 않는다. 앱 종료 후 새 프로세스가 설정을 읽는다.
- 우선순위는 mock 강제 오프라인 → 명시적 SDSTUDIO_OFFLINE(정확히 0만 온라인, 나머지는 오프라인) → 명시적 개발 프로필 기본 오프라인 → 일반 포크의 저장 설정이다. 앞 세 경우는 화면에서 변경하지 못한다. explicit과 active를 구분하되 모든 포크 실행의 데이터 격리는 유지한다.
- userData/network-mode.v1.json에는 version과 mode만 저장한다. 손상·초과 크기·미지원 버전은 오프라인으로 시작하고 기존 바이트를 보존한다. 명시적인 설정 초기화는 이 파일만 지우며 토큰/프로젝트를 건드리지 않는다. 정상 쓰기는 wx/0600 임시 파일과 rename을 사용한다.
- network-mode-status/set/reset/restart는 기존 인증과 같은 창·최상위 프레임·문서 검사로 제한한다. 로컬 시작 설정이라 오프라인에서도 허용한다. nai-auth-*는 계속 오프라인에서 저장소 접근 전 거부한다. 서버 인증·이미지 생성 성공으로 표시하지 않는다.
- 재시작 확인 후 V3 saveAll을 기다린다. 저장 실패, 예약·실행 중인 작업이 있으면 중단하고 저장한 다음 모드는 유지한다. stop/clear 뒤에도 끝나지 않은 V3 run promise를 추적하며 저장 전후 모두 재확인한다. 임시 초안/예제 기록·세션 토큰 소실은 확인창에 표시한다.
- 앱의 실제 relaunch/quit를 사용한다. 중복 재시작 IPC를 거부하고 제어된 재시작 때만 기존 close 저장 루프를 우회한다. 일반 창 닫기의 기존 저장 동작을 전면 변경한 것은 아니다. 다른 close 핸들러는 유지한다.
- Linux 실제 패키지의 서로 다른 세 PID, 두 번의 native 재시작으로 오프라인→온라인→오프라인과 프로젝트 보존을 검증한다. 단일 인스턴스 잠금만 환경 제한으로 모의 처리하며 원격 요청은 검사 하네스에서 추가 차단한다.


## D-029 — 기존 V3 로그인은 새 API 토큰과 구분해 고지한다 (PR #12 검토)

- 기존 로그인 기능을 숨기거나 토큰 저장 형식을 바꾸는 대신, 환경설정에 이메일·비밀번호 사용 및 TOKEN.txt 평문 저장을 명시한다. 상단의 로그인 유도는 V3 로그인 상태로 바꾸며 새 API 토큰과 별도임을 표시한다. 새 경로의 보안 보관 원칙을 기존 V3에도 적용했다고 주장하지 않는다. 기존 토큰을 새 보관소로 자동 이관하지 않는다.
- 재시작 차단은 V3 실행/종료 중, V3 예약, 새 작업실 대기열로 구분한다. 남은 개수가 0이어도 비동기 run이 끝나야 한다는 안내를 제공한다. 저장 전후 재확인과 실제 재시작은 유지한다.
- 현재 종료 취소 지점은 mainWindow의 기존 close 저장 처리이며 제어된 재시작 때 건너뛴다. 로컬 AI close 정리와 before-quit 토큰 lock은 종료를 취소하지 않는다. 추가 종료 취소 핸들러 도입 시 relaunch 수명 처리를 먼저 재검증한다. 예약된 relaunch를 취소할 방법 없이 일정 시간 후 플래그만 되돌리면 중복 시작 위험이 있어 타이머 복구를 이번에 추가하지 않는다. Linux 재시작 성공 검증은 취소 복구나 Windows/macOS 검증이 아니다.
- 연결 모드의 일반 설정 편입/배지 바로가기·버튼 통합은 P1 화면 연결 때 다룬다. 현재 저장만 한 뒤 나중에 재시작하는 선택과 별도 확인을 유지한다.

## D-030 — 실제 모델 연결 전, 메인에서 단일 PNG 응답을 제한해 검증한다

- main/nai/imageResponse.ts는 Node zlib의 비동기 스트림으로 제한된 ZIP 형식을 읽는다. ZIP 최대 64 MiB, PNG 최대 32 MiB, 픽셀 수 최대 16,777,216은 우리 자원 정책이며 서버 규격이나 과금 기준이 아니다. 입력을 await 전에 복사하고 선언 크기 검사와 실제 출력 크기 제한을 모두 적용한다.
- 단일 PNG 엔트리, STORE/DEFLATE, ASCII 상대 경로, 일반/스트리밍 data descriptor만 허용한다. ZIP64·암호화·분할 볼륨·SFX/중복·부가 파일·디렉터리 엔트리·심볼릭 링크를 거부한다. 헤더/디렉터리/descriptor 대응, ZIP CRC와 PNG 청크 CRC·IHDR/IDAT/IEND 구조·크기 한도를 확인한다. 파일시스템 추출·PNG 재인코딩은 없다. 이미지 픽셀/IDAT 전체를 디코딩하거나 메타데이터 내용을 실행/신뢰하지 않는다.
- 이 좁은 ZIP 응답 형식은 실제 NovelAI 응답에서 확인된 호환 범위가 아니다. 실제 응답이 다르면 명시적 오류로 남기고 근거를 확보해 지원 범위를 별도 변경한다. 기존 readPreviewPNGZip은 오프라인 fixture용이고, 운영 연결에는 메인 sendImage를 사용해야 한다.
- NaiTransport.sendImage는 send와 해제에 하나의 기한·AbortSignal을 사용한다. 응답 이후 ZIP/PNG/크기/기한/취소 오류는 mayHaveReachedServer=true로 기록하며 자동 재시도하지 않는다. 비 2xx HTTP_ERROR와 2xx MIME 거부 RESPONSE_FORMAT을 구분한다. 원시 오류 본문·파일명·토큰·프롬프트는 오류에 넣지 않는다.
- 메인 sendImage는 내부 호출용이며 생성 IPC·모델 바인딩·새 프로젝트 저장·실제 대기열 연결은 아직 없다. 공식 스키마의 model은 string이고 모델별 enum/action/params_version 기본값은 계속 미확인이다. 합성 로컬 응답 검증을 실제 계정 생성 성공으로 표시하지 않는다.


## D-031 — 실패 원인은 내용 없는 내부 코드로 남기고 로컬에서 재검사한다 (PR #13 검토)

## D-034 — 첫200/ZIP 조각 응답을 반영해 연구 수신과 중단 기록을 보완한다

- 첫1회 실제 요청의 사용자 정제 기록은 HTTP200·MIME분류other·ZIP flags8/method8·64KiB잘림·잔액 관찰차이0이다. 계정 잔액/토큰/본문/이미지는 공개하지 않는다. PNG 전체·정확한 MIME·개별 청구·캐릭터/시드 의미는 미확인이다. 요청 해시는 기존 후보와 같으며 seed0을 지금 바꿔 이력을 끊지 않는다.
- 연구 entry만 acceptZipSignature와 capture를 함께 켠다. 2xx 미분류 MIME은 최대4바이트를 모아 PK0304면 수신 상한을64MiB로 적용하고 원문 보관 후 기존 ZIP/PNG 검사로 넘긴다. 이는 수신 경로 선택이지 검증 성공이 아니다. 모든 기존 크기/CRC/구조·취소/기한 검사를 유지한다. 비2xx/비ZIP/기본 운영 옵션은 기존 정책이다.
- 결과 파일 없는 used 프로필도 현재 인스턴스 실행 중이 아니면 후잔액 기록을 허용한다. incomplete=true/resultRecord=missing을 붙이고 실제 완료/청구를 추정하지 않는다. 다른 실행 창이 종료됐는지 사용자가 확인하도록 안내한다. 다른 프로세스의 생존을 판정하는 기능은 아니다. 실행 중인 현재 인스턴스는 기록을 거부하며 기존 wx/해시/미지원 버전 보존·재전송 금지는 유지한다.
- elapsedMs는 전송·보관·해석의 경과 시간이다. 결과 파일 없이 끝난 과거 시도의 처리 시간을 복원하거나 자동 성공/실패 result를 만들지 않는다.
- 기존 사용자 실험 위임 안에서 이번 클라이언트 MIME 수정의 검증을 위한 추가1회만 계획한다(전체2회). 원래 요청/해시를 유지하고 새 명시적 프로필에서 동일 설정 웹 비용·잔액을 다시 확인한다. 최초 attempt.displayedCost와 새 표시 비용의 합계10 Anlas 이내일 때만 사용자가 전송한다. 첫 표시 비용을 확인할 수 없으면 추가 전송하지 않는다. 잔액 차이0은 무료 증명이 아니다. 자동 재전송/프로필 생성/이전 기록 삭제는 없다. 후속이 실패하면 원문 보관부터 분석하고 다른 호출은 재검토한다.


## D-035 — 기본1장 실측 완료와 Anlas/사용량의 의미를 구분한다

- 사용자가 두 번째 요청의 ok=true, ZIP609317/PNG609129바이트, acceptedByZipSignature=true/captureTruncated=false, 약8초를 보고했다. 첫 요청과 동일 해시/후보이며 엄격 ZIP/PNG 구조검사·원본저장 경로를 통과한 기본1장 실측으로 기록한다. 픽셀/화질·metadata모델/seed·캐릭터 의미까지 확인한 것으로 확대하지 않는다.
- 실제 계정 잔액·계정/토큰·원문·이미지는 공개하지 않는다. Anlas 관찰차이0, 사용자 Opus설명, 사용량 전후미측정을 구분한다. 공식 구독 문서는 V4.5초과 모델의usage limit과 V4.5이하의 조건부 무료생성을 구분한다. 이번 V4.5에서 할당량이 줄었다고 추정하지 않는다. 무료조건은 구독 이름만으로 앱이 결정하지 않는다.
- 현재 창은 웹 표시Anlas비용/잔액만 기록한다. Opus등 조건부무료이면 실제 웹표시0을 입력할 수 있지만, 할당량을 측정하거나 “사용량소모없음”으로 표시하지 않는다. 문구를 보완하고 비용·한도 로직이나 계정API는 추가하지 않는다.
- 첫 실측2회는 완료다. 반복 호출을 요청하지 않고 다음은 신규 프로젝트 저장/읽기/복구와 원본PNG보존을 합성 데이터로 구현한다. V3세션 자동변환·대기열 연결·모델별 세부기능은 별도 작업이다.

## D-036 — 운영 이미지 수신은 MIME보다 제한된 ZIP·PNG 검증으로 판정한다 (PR #16 검토)

- PR #16 head `5687db7`, 병합 `c87380a3db6fd83cc7150320b71a75087df1cfb4`의 두 사용자 실측에서 정확한 MIME 문자열은 남지 않았다. Gemini 의견 중 “실제 문자열을 확인해 두었을 것”은 사실로 채택하지 않는다. `binary/octet-stream` 등을 추측해 허용 목록에 넣지 않는다. 추가 실호출 없이 합성 응답과 Linux Electron으로 운영 기본값을 검증한다.
- 운영 `NaiTransport.sendImage()`는 진단 보관이나 연구 옵션 없이도 2xx 미분류/미지정 MIME의 첫 4바이트 `PK\x03\x04`를 청크 경계에 걸쳐 확인해 최대 64 MiB를 수신한다. 그 뒤 기존 단일 엔트리 ZIP·PNG 구조/CRC·해제 크기/픽셀 제한을 모두 통과해야 성공이다. 시작부만 맞는 가짜 ZIP은 성공하지 않는다. 비 2xx는 이 대체 수신을 허용하지 않으며 비 ZIP 오류 본문은 운영에서 보관하지 않는다.
- 원문 바이트를 돌려주는 `send()`의 기본 MIME 정책은 유지한다. 연구 도구는 capture와 acceptZipSignature를 함께 지정하고 해석 전 비공개 원문을 보관한다. 제품 연결은 반드시 `sendImage()`를 사용하며 원문 `send()`를 이미지 검증 대신 쓰지 않는다. 전송/해제의 공유 기한·취소·오프라인 선행 거부·mayHaveReachedServer·자동 재시도 금지는 유지한다.
- 선택적인 메인 observer는 HTTP 상태와 정제된 MIME만 받는다. 헤더 원문은 최대 512자, CR/LF/NUL 거부 후 세미콜론 파라미터를 버리고 소문자 type/subtype을 `^[a-z0-9.+-]{1,40}/[a-z0-9.+-]{1,60}$`로 제한한다. `present`/`absent`/`invalid`를 구분하며 원시 헤더·파라미터·본문·토큰을 콜백에 넣지 않는다. 이는 형식 제한이며 임의 문자열의 비민감성을 증명하는 것은 아니다. 자동 로깅/운영 IPC 반환을 추가하지 않는다. observer 예외는 전송을 실패시키지 않는다.
- 연구 결과 저장 시에도 MIME을 다시 정제한다. 예전 other 기록을 사후에 특정 MIME으로 바꾸지 않는다. 새 합성 MIME은 테스트 값일 뿐 실제 서버 MIME의 근거가 아니다. LiveValidation의 active 해제는 시도 선점 뒤 전체 본문 바깥 finally로 보장한다.
- P1-02 실제 대기열 연결 때 앱은 비용·무료 조건·할당량을 계산하지 않는다고 표시한다. 예약 수·설정과 웹 비용 확인을 묶어 실행 전에 한 번 확인하고, 예약/설정 변경 시 확인을 다시 받는 흐름을 구현한다. 이미지마다 확인하거나 자동 재시도하는 흐름은 만들지 않는다. 현재 mock 큐는 바꾸지 않으며 사용자 Opus/Anlas 관찰차이0에서 사용량 소모를 추정하지 않는다.
- Windows Node 22.4.1 준비는 기존 재현 기준으로의 정렬이다. VS2026을 인식하지 못하는 로컬 @electron/node-gyp10.2.0-electron.1 문제의 해결과 구분한다. 전체 Windows npm ci·네이티브 빌드·패키징 호환은 미검증이며 의존성 변경은 별도 작업이다.
