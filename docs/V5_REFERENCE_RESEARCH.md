# V5 이미지 참조 조사와 후속 설계 — D-057

확인일: **2026-11-25 (Asia/Seoul)**. 기준 코드: PR36 `f6f705a`. 이번 변경은 조사/문서만이며 참조 전송 기능을 구현하거나 실계정을 호출하지 않는다. PR36의 PNG 가져오기와 캐시 보강은 그대로다.

## 현재 공식 근거

가장 최근의 [V5 출시 공지](https://journal.novelai.net/precise-reference-v5/) 본문을 직접 확인했다. 일반 검색/직접 요청은 접근 실패했고, 별도 페이지 수집 경로의 live HTTP200 본문으로 대조했다. 게시일의 정확한 시간대는 확인하지 않았으므로 확인일과 출시 시각을 구분한다.

| 공지에서 확인한 항목 | V5 내용 |
| --- | --- |
| 모델 | Full·Curated 지원 |
| 참조 대상 | 캐릭터·화풍·새 의상 참조와 조합 |
| 의상 옵션 | 캐릭터/캐릭터+화풍에서 같은 의상을 더 따르는 선택 |
| 조절 | Fidelity 제거, Strength 단일 슬라이더 |
| 인페인팅 | 참조를 사용하는 인페인팅은 아직 미지원 |

공지는 참조 이미지당 **5 Anlas**를 명시한다. 사용자의 이전 일반 V5/Opus 생성에서 Anlas 관찰 차이가0이었던 것과 구분한다. 참조를 써도 할당량만 줄 것이라고 가정하지 않는다. 앱의 최종 가격 계산/무료 판정 근거를 확보한 것은 아니다.

[기존 참조 도움말](https://docs.novelai.net/en/image/precisereference/)에는 여전히 V4.5 전용·Fidelity·인페인팅 지원이라는 설명이 있다. 이 부분을 신규 V5 제약으로 옮기지 않는다. [V5 최초 출시 글](https://journal.novelai.net/image-generation-novelai-diffusion-v5-is-here-c2df7c6b8d2d/)의 ‘출시 당시 참조 미포함’도 과거 시점의 설명이다. 최신 공지로 현재 기능을 판단하되, V5의 Vibe Transfer 지원/참조 동시 사용 조건은 별도 확인 대상으로 남긴다.

## 후속 구현 제안 — 아직 제품 계약 아님

1. **우선은 V5 Full·참조1장.** 사용자가 평소 쓰는 모델부터 연결하고 기존 무참조 요청의 본문/바인딩은 그대로 보존한다. 조합 가능한 참조 역할·강도·의상 옵션을 카드로 표시한다. 수치 범위/기본값/직렬화 방식은 현행 API 근거를 확인한 뒤 정한다. Curated 앱 바인딩과 다중 참조는 별도 확장한다.
2. **드래그 목적 선택.** 같은 PNG를 놓아도 ‘입력 정보 가져오기’와 ‘생성 참조로 사용’을 구분한다. 로컬 가져오기를 했다는 이유로 이미지가 서버 전송 대상이 되지 않는다. 참조 카드에는 생성 시 이미지를 전송한다는 사실을 짧게 표시한다.
3. **프로젝트 자산.** 참조 원본은 결과 PNG와 구분해 UUID/내용 해시로 관리한다. 프로젝트 재열기/복사/복구 시 참조가 유실되면 전송 전에 알리고, 텍스트 생성이나 V4.5로 자동 전환하지 않는다. 저장 형식이 실제로 바뀌는 범위에서만 버전을 결정한다. 원본과 업로드용 파생 이미지의 역할도 구분한다.
4. **같은 실행 경로.** prepare의 확인 사본에 참조 해시·역할·강도·옵션을 묶고 실행 때 변화를 확인한다. 기존 단일/직렬 큐·중지·응답 PNG·미저장 결과 저장-only를 재사용한다. 바인딩/리비전 확인·중복 전송 금지는 유지한다.
5. **사용량 안내.** 단일 생성은 참조 카드에 추가 비용 안내를 두고 현재 원클릭 동선을 유지하는 방향이다. 큐는 기존 묶음 확인에 요청 수·참조 수/조건을 넣는다. 최종 요금/무료 여부를 보증하거나 이미지마다 새 확인을 요구하지 않는다. 가격표와 Opus 다중 이미지 예외는 실행 조건과 함께 확인한다.
6. **합성 우선.** 파일 선택/해제·잘못된 역할/상한·큐 승인 뒤 참조 변경·중지·저장-only·프로젝트 복구를 합성 PNG/루프백으로 확인한다. 첫 실호출이 필요하면 그 시점에 사용자가 고른 참조·설정·요청 범위로 진행하며 키는 앱에서 직접 입력한다.

## 구현 전에 남은 확인

- 현재 이미지 API의 참조 필드/조합 표현과 V5에서의 의상 옵션 wire 값. V4.5의 필드/배열을 추측으로 재사용하지 않는다.
- 이미지 전처리 크기/패딩/형식·알파 처리, 업로드 크기와 전체 요청/큐 메모리 상한. 공지의 여러 참조 허용 설명은 앱의 무제한 자산/메모리 허용을 의미하지 않는다.
- 여러 캐릭터의 독립 대응 여부와 텍스트 캐릭터 배열/수동 좌표와의 상호작용. V4.5의 혼합 동작을 V5에 단정하지 않는다.
- 실제 PNG에 참조 설정이 얼마나 들어오는지. 메타데이터만으로 원래 참조 이미지까지 복구했다고 표시하지 않는다.
- V5 참조 인페인팅·Vibe 병용은 각각 지원 근거가 생길 때 별도 바인딩/검증한다. 공식 사이트의 UI/코드/이미지 자산을 복사하는 작업은 아니다.

이번에는 운영 코드/스키마/요청·기본값을 변경하지 않았다. 개인 이미지/키 입력·실계정 호출0회다.
