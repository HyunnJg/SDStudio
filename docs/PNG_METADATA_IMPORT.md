# PNG에서 현재 씬 입력 가져오기 — D-056

기준: PR35 병합 `b3fb84b`. 작업실에 PNG 한 장을 끌어놓거나 중앙 상단 ‘PNG 정보 가져오기’를 누른다. 미리보기에서 기본 프롬프트·부정 프롬프트·캐릭터 텍스트·생성 설정·시드를 골라 현재 씬에 적용한다. 파일이나 이미지 기록을 프로젝트에 자동 추가하지 않으며 저장/생성은 기존 버튼으로 따로 실행한다.

## 적용 범위

| 선택 | 동작 |
| --- | --- |
| 기본/부정 | v4 caption의 base_caption 우선, 없으면 prompt·uc/negative_prompt를 읽는다. 원래 텍스트를 보존하며 조각 전개·공백 정리·길이 잘라내기를 하지 않는다. |
| 캐릭터 | 파일 배열 순서로 긍정/부정을 대응해 새 로컬 UUID로 현재 캐릭터 목록을 대체한다(빈 목록은0명으로 대체). 개별 부정 누락은 빈 문자열, 개수 불일치·22명 초과·비문자열/초과 길이는 캐릭터 항목을 제공하지 않는다. 캐릭터를 고르지 않으면 기존 비활성 입력도 유지한다. |
| 생성 설정 | **현재 선택 모델을 유지**하고 그 경로가 지원하는 크기·스텝·가이던스만 적용한다. V5는832×1216/1216×832/1024×1024·1~50·0초과10이하, V4.5는기존512/28/5 조합이다. 원본 Source에서 모델을 추측해 바꾸지 않는다. |
| 프리셋 | ‘생성 설정’ 선택 시 품질·UC 자동 추가를 none으로 둔다. 파일 caption에 들어 있는 최종 태그를 다시 붙이지 않기 위한 앱 선택이며 원본 프리셋 ID를 복원한 것은 아니다. 화면에서 명시한다. |
| 시드 | 0~4294967295 정수만 고정 모드로 적용한다. 0도 유효하다. 시드를 고르지 않으면 기존 모드/입력을 보존한다. |

수동 좌표·현재 앱이 지원하지 않는 sampler/schedule/CFG rescale/고급 설정·Image2Image/참조/Vibe는 적용하지 않는다. 캐릭터 선택은 **텍스트·자동 배치**라고 표시하고, 원본 좌표가 있으면 적용 제외 안내를 한다. CFG rescale0.2를 읽어도 현재 전송의0을 몰래 바꾸지 않는다. 지원하지 않는 크기/스텝/가이던스는 현재 값을 유지한다는 안내와 실제 적용할 값이 보인다. 같은 그림 재현을 보장하지 않는다.

모델·프롬프트 생성 가능성은 기존 main 바인딩이 최종 검사한다. `|`/미전개 조각 등 편집용 텍스트도 가져오기 단계에서 임의로 지우지 않는다. 적용은 현재 draft만 바꾸며 준비 중이던 확인 계획은 비우고, 기존 큐가 있으면 다음 요청 전의 기존 입력 비교가 변경을 감지한다. 다른 씬과 저장 PNG는 유지한다. 캐릭터 대체 시 선택 ID와 삭제 취소 수명도 갱신한다.

## 읽기와 수명

- 입력은 PNG32MiB·16,777,216픽셀·4,096청크 이하. signature/청크 경계/CRC·IHDR/IEND·IDAT 존재를 확인한다. 이는 이미지 파일 형식 검사의 일부이며 모든 픽셀 해석·진위/서명 인증을 보장하는 검사는 아니다.
- tEXt·zTXt·iTXt의 Comment JSON과 부가 텍스트를 읽는다. 일반 텍스트 Comment가 읽히면 우선하고, 없거나 해석되지 않으면8bit RGBA의 `stealth_pngcomp` 알파 LSB를 읽는다. RGB 은닉/비압축 stealth/EXIF·WebP·FEC/서명 검증은 이번 범위가 아니다.
- 알파는 열→행 순서, 바이트 MSB 우선, 길이는32bit big-endian 비트 수, 본문은gzip JSON이다. PNG 픽셀은 Chromium의 createImageBitmap/OffscreenCanvas로 읽고 재인코딩하거나 원본을 쓰지 않는다.
- 압축 입력/수집 출력512KiB 상한. 압축 입력을1KiB씩 공급하고 Web DecompressionStream의 출력 누적을 확인한다. 브라우저 내부 할당량 전체의 절대 상한을 보증하지는 않는다. PNG 전체는32MiB, 픽셀 버퍼는최대16MP이므로 큰 파일의 일시 메모리·CRC 비용은 남는다.
- 파일 읽기/픽셀 해석 대기 뒤에 취소를 재확인한다. 닫기·파일 교체·프로젝트/씬/모델 변경으로 이전 읽기를 무효화하고 bitmap과 미리보기 object URL을 정리한다. 이미 시작한 native decode 자체를 중간 취소하는 API로 설명하지 않는다.
- File/bytes는 renderer 로컬에서 처리한다. 파일 경로·PNG 업로드·쓰기용 IPC/네트워크·새 권한은 추가하지 않는다. OS 예외/파일명/서버 본문을 오류 문구로 출력하지 않고, JSON 내용은 React 텍스트로만 보여준다. 실행/저장 중에는 적용을 막는다.

## 공식 근거와 독립 구현

- [NAI FAQ](https://docs.novelai.net/en/faq/): 저장한 파일의 프롬프트/설정/시드와 드래그 가져오기. [seed 안내](https://docs.novelai.net/en/image/seed/): 모든 설정과 참조 이미지가 같아야 하며 항상 동일한 결과가 보장되지는 않음(2026-11-25 확인).
- [PNG3 텍스트 청크](https://www.w3.org/TR/2025/REC-png-3-20250624/): tEXt/zTXt/iTXt 프레임과 압축 필드.
- [NovelAI/nai_meta.py](https://github.com/NovelAI/novelai-image-metadata/blob/3428907ac7183d7e36d7cc39e8f46f6f35ce99c1/nai_meta.py): 알파 LSB 순서·magic·비트 길이·gzip/Comment 구조 확인. 같은 리비전 LICENSE는MIT/NovelAI2023이다. Python 코드·자산·의존성은 가져오지 않고 브라우저용으로 독립 구현했다. PNG CRC 함수는 이 저장소의 기존 imageResponse 구현을 공통 순수 모듈로 이동해 사용한다.

[검증](validation/2026-11-25-png-metadata.md). 실계정·개인 PNG는 사용하지 않았다.
