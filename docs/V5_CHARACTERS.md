# V5 캐릭터 프롬프트·자동 배치 (D-054)

2026-11-25 (Asia/Seoul), 기준 main `f7aa35e`(PR33 병합). 사용자가 다음 기능으로 V5 캐릭터 프롬프트를 선택했다. 이번 범위는 별도 긍정/부정 입력, 활성화·순서, 자동 배치와 기존 단일/반복 생성·PNG 보관 연결이다. 실제 계정 생성은 이번0회이며 서버 수용/배치 품질은 합성 검증과 구분한다.

## 근거와 자체 선택

- [공식 다중 캐릭터 설명](https://docs.novelai.net/en/image/multiplecharacters/)에서 V5 최대22명·기본/캐릭터 입력 분리·순서·부정 조건을 재확인했다. 순서는 모델이 참고하는 조건이며 화면상의 위치를 보장하지 않는다.
- [공식 Image API 스키마](https://image.novelai.net/docs/doc.json)의 `image.V4ConditionInput`, `V4ExternalCaption`, `V4ExternalCharacterCaption`에서 caption/char_captions/char_caption/centers와 use_coords/use_order/legacy_uc 필드 타입을 확인했다. 문서의 V4 접두사를 V5 미지원으로 해석하지 않는다. 기존 V5 바인딩도 이 구조를 쓴다.
- [공식 공개 클라이언트 청크](https://novelai.net/_next/static/chunks/36juzcfi11xq3.js)를 2026-11-25 수집 도구로 재확인했다(rawHtml 35,898자). 양성·음성 char_captions를 같은 활성 목록에서 만들고 각 centers 배열, 양성 use_order/use_coords·음성 legacy_uc를 구성하는 사실을 확인했다. 오래 유지되는 API 계약/전체 클라이언트 동일성을 주장하지 않는다. 원문 구현/청크는 저장소에 복사하지 않았다.

앱은 **긍정 입력이 있는 활성22명 이하·자동 배치**로 제한한다(D-059). 빈/공백 긍정 카드는 작성 대기로 저장하고 전송에서 제외한다. 부정만 있어도 작성 대기이며 부정은 보관만 한다고 표시한다. V5는 전송할 캐릭터가 있으면 기본 프롬프트가 비어 있어도 준비할 수 있다. 양성/음성 char_captions는 이 동일 목록의 순서로 만들며 부정 입력이 비어 있어도 빈 대응 항목을 유지한다. 기본 품질 태그/UC 프리셋은 기본 조건에만 적용한다. source#/target#/mutual# 텍스트는 그대로 보존하고 효과를 보장하지 않는다. 인원수 태그를 추측해 자동 삽입하지 않는다.

2026-11-25 공식 API 스키마의 input/base_caption/char_caption은 string이며 minLength가 없음을 재확인했다. 이를 근거로 앱의 기본 입력 필수 조건을 완화한 것이며, 빈 기본 caption의 실서버 수용·배치 품질을 검증한 것은 아니다. 기본/전송 가능한 캐릭터 모두 없으면 전송 전에 INVALID_INPUT으로 멈춘다. V4.5의 기본 프롬프트는 계속 필수다. [검증과 한계](validation/2026-11-25-character-input-flow.md).

`use_coords=false`, 양성 `use_order=true`이며 centers는 중립값 `{x:0.5,y:0.5}` 한 개를 둔다. **중립값은 이 앱의 선택**이며 사용자 grid cell을 API 좌표로 투영한 값이나 공식 default를 실측한 값이 아니다. 기존 cell·수동 위치 초안은 저장하되, 활성 캐릭터가 수동 모드면 보내지 않고 사용자가 자동 배치로 바꿀 때만 전환한다. V4.5 캐릭터·수동 좌표·`|`·조각/와일드카드 전개는 이번에 열지 않는다. 비활성 항목의 미완성 입력은 보존하고 API 조건에서 제외한다.

## 화면·실행·저장

V5 캐릭터 패널에서 추가/긍정·부정/켜기·끄기/위·아래/삭제·마지막 삭제 취소를 제공한다. 생성 대상22명과 작성 대기를 포함해 저장 가능한 전체32개 한도를 구분한다. 프로젝트·씬이 바뀌면 삭제 취소 상태를 분리하며 중복 ID로 복원하지 않는다. 생성/미저장 PNG/프로젝트 작업 중에는 기존 fieldset 잠금이 편집도 막는다. V4.5로 바꿔도 기존 입력을 삭제하지 않으며 기존 “캐릭터 조건 끄기”로 비활성화할 수 있다.

단일 클릭과 큐의 같은 prepare→execute→sendImage→pending→persist를 쓴다. 확인창에는 활성 캐릭터 수·자동 배치를 표시하고 묶음의 서로 다른 수를 별도 설정 요약으로 구분한다. 큐의 draft 충돌 검사·미전송 제외·저장-only 복구·일회용 승인/자동 재시도 금지는 유지한다. 캐릭터 추가/편집/예약만으로 네트워크를 보내지 않는다.

활성 캐릭터가 없는 요청의 본문과 `nai-v5-full-v1`은 그대로다. 캐릭터 요청만 `nai-v5-characters-auto-v1` 바인딩과 실제 body SHA-256을 기록한다. 결과의 전체 원본 draft에는 비활성 항목·순서·cell도 보관한다.

새 바인딩 결과가 생길 때 manifest **v4**가 필요하다. 입력만 저장한 기존 V5 프로젝트는 v3이며 불필요한 승격을 하지 않는다. reader는 v1~v4를 읽고, v4 복사/재열기와 직전 v3 이력의 새 UUID 복구를 유지한다. v4 결과를 v3라고 속인 파일은 거부한다. v4를 모르는 이전 reader는 PROJECT_VERSION으로 거부하므로 파일을 덮어쓰지 않는다. 화면에 이전 앱에서 열 수 없음을 안내한다.

[단위·실제 창/worker 검증](validation/2026-11-25-v5-characters.md). 토큰·실제 계정 이미지·원문 응답은 필요하지 않다. 실계정 확인이 필요해지면 사용자 앱 안의 기존 입력 경로를 쓰며 채팅으로 키를 받지 않는다.
