## 문장 대신 상태

저장/준비/전송/응답 검사/각 결과 저장 같은 내부 단계를 매번 완료 문장으로 내보내지 않는다. 처리 중에는 버튼 상태와 대기열 숫자, 저장 여부는 이름 옆 표시로 구분한다. 완료는 원본 PNG와 manifest 저장이 실제 성공한 뒤에만 표시하며, 실패·서버 처리 불확실성·미저장 PNG 복구와 사용자 결정을 요구하는 안내는 남긴다. 단순 파일 가져오기·적용·예약 제외의 성공 문장은 생략한다. 자세한 사유 코드와 진단 파일은 기존 내부 경로에 남는다.

라이브러리는 저장/미저장·선택 강조·종류별 개수로 상태를 보여주고, 작업실에는 적용한 프리셋 이름을 표시한다. 적용 뒤 관련 텍스트가 바뀌면 ‘수정됨’을 붙인다. 저장하지 않은 편집본 적용은 ‘편집본’으로 구분한다. 적용 흔적은 renderer 메모리이며 저장 스키마에는 추가하지 않는다. 다시 연 프로젝트는 저장된 텍스트/프리셋 설정이 정확히 같은 라이브러리 항목만 이름을 추정 표시한다. 시드·모델·참조 변경은 프리셋 텍스트 수정으로 세지 않는다. 여러 항목이 정확히 같으면 최신 항목 이름이다.

## 이미지 입력과 비용

이미지 추가/드롭은 파일 선택 뒤 ‘프롬프트·설정 가져오기 / 이미지 레퍼런스’를 고른다. 선택 자체로 업로드/생성이 일어나지 않는다. V4.5에서는 로컬 가져오기는 되지만 레퍼런스 선택은 비활성이다. 이미 저장된 결과는 중앙의 명시적 목적 버튼으로 재사용하며 같은 UUID 제한 읽기를 쓴다. PNG 원본은 바꾸지 않는다. i2i는 아직 지원하지 않으므로 실행 가능한 척하는 선택지를 만들지 않는다.

PR39 검토의 참조 비용 지적은 세션 최초 확인 + 상시 배지 대안을 채택했다. 첫 참조 단일 생성 전에 추가5 Anlas를 확인하고 취소 시 전송0, 확인 후 같은 renderer 세션에서는 다시 묻지 않는다. 높은 스텝 확인은 계속 별도이며 반복 묶음은 매번 총 건수/설정/비용 확인을 유지한다. 단일 일회용 티켓·메인 전송/재시도 경계는 그대로다. 배지는 참조가 있는 동안 생성 버튼에 남는다. 확인은 서버의 강제 청구 상한이나 무료 판정이 아니다.
