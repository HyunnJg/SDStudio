## 변경한 동작

`SDSTUDIO_USER_DATA_DIR`가 있을 때 `main.ts`의 첫 import에서 프로필을 선택한다. 원본 `DEFAULT_APP_DIR` 상수, 로깅, 네이티브 의존성보다 앞이다. userData·Chromium sessionData·로그·crashDumps를 선택한 경로 아래로 지정한다.

원본과 겹치는 경로, 대소문자만 다른 Windows/macOS 경로, 원본으로 되돌아가는 심볼릭 링크를 거부한다. 개발 프로필이 활성화되면 config의 `saveLocation`을 저장 위치로 사용하지 않는다. 환경변수가 없을 때 기존 저장 동작은 유지한다.

`profile:check`는 실제 앱 진입점에서 경로를 출력한 뒤 설정·토큰 읽기와 서비스 시작 전에 종료한다. 전체 UI를 실행한 검증이 아니다. 경로 선택은 [Electron의 ready 이전 경로 설정 지침](https://www.electronjs.org/docs/latest/api/app#appsetpathname-path)에 맞춘다.

소스 진입점과 빌드 번들에서 확인한 로그 형식:

```json
{"userData":"/tmp/sdstudio-profile-check","appDirectory":"/tmp/sdstudio-profile-check/SDStudio","checkOnly":true}
```

테스트는 합성 프로필로 수행했다. Windows/macOS의 실제 파일시스템·기동은 미검증이며 사용자 PC의 기존 프로필을 백업한 결과도 아니다. Linux의 시스템 버스 접근 경고는 있었지만 드라이런 종료 코드는 0이었다.

## 설치 중 발견한 문제와 처리

1. 원본 `devEngines.node`/`npm`은 현재 npm이 허용하는 devEngines 구조가 아니어서 lifecycle의 하위 npm 실행이 실패했다. 기존 최소 버전 표기를 표준 `engines`로 옮겼다.
2. 범위 지정으로 설치된 libsodium wrapper `0.7.16`이 존재하지 않는 상대 ESM 파일을 참조해 DLL 빌드가 실패했다. 원본 지정 범위의 시작 버전인 wrapper/sumo `0.7.13`으로 고정했다. 모델·로그인 알고리즘 변경은 없다.
3. 원본 린터 설정이 요구하는 prettier 플러그인이 루트에서 해석되지 않았다. 호환되는 루트 `eslint-plugin-prettier`와 `eslint-config-prettier`를 명시했다. 강제 peer-deps 무시는 사용하지 않았다.
4. 루트·배포·네이티브 패키지의 lock 파일을 추적하고 Node 버전 기준을 기록했다. lock URL은 공개 npm/GitHub 출처이며 비밀번호·환경의 절대 경로가 없는지 확인했다.

## 재현 명령

Node `22.4.1`에서 background-mode 서브모듈을 초기화한 체크아웃을 사용한다.

```sh
git submodule update --init externals/capacitor-background-mode
npm ci
npm run build
npm run test:profile
npm run test:profile:electron
```

새 모듈만 검사한 타입검사 명령:

```sh
npx tsc --noEmit --skipLibCheck --strict --esModuleInterop --target es2022 --module commonjs --types node src/main/developmentProfile.ts src/main/profileBootstrap.ts
```

전체 UI 기동은 P0-02 이후 `npm run start:isolated -- /절대/개발프로필`로 별도 확인한다.
