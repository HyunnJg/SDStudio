## 실제 전송 경계 검사의 의미

인증 하네스는 임시 appData/userData와 합성 키만 사용했다. main 전체를 로드하는 대신 실제 preload 번들과 생산 코드의 저장소/IPC/네트워크 훅·전송 모듈을 호출한다. 인스턴스 잠금 모의는 이 하네스에 필요 없다. 저장소 원본/사용자 프로필은 읽지 않는다.

전송 자체가 offline이면 토큰 조회 0건이다. 다음에는 전송의 offline 플래그만 의도적으로 열어도 **생산 코드와 같은 defaultSession 훅**이 고정 원격 목적지를 취소함을 확인했다(`ERR_BLOCKED_BY_CLIENT`, 취소 결정 1건). 실제 서비스에 요청이 전송된 것이 아니다. 정상 응답 시험에는 테스트 wrapper만 URL을 루프백 서버로 바꿨다. 공유 오프라인 훅은 그대로 유지했다. 서버는 합성 쿠키가 있는 세션에서도 Authorization만 받고 Cookie는 받지 않았다. ZIP bytes가 그대로 반환됐고 307은 두 번째 HTTP 요청 뒤에 따라가지 않았다(정상 1건 + 307 1건, 서버 접수 총 2건).

실험 중 Electron의 writable finish/close가 응답보다 먼저 발생해 close만으로 종료하면 정상 요청이 실패함을 발견했다. 응답/기한 기반으로 수정하고 단위 회귀와 실제 루프백 성공으로 확인했다. 초기 별도 startup 검사에서는 잠금 모의 환경변수 누락으로 기존 Unix socket 제약에 걸렸고, 기존 하네스 옵션을 적용한 최종 실행은 통과했다.

## 한계

- 실사용 토큰·계정 조회·모델 생성·과금 모두 없음. 생성 UI/큐에 전송기를 연결하지 않았다.
- 실제 Linux 키링은 없는 환경이다. **실제 Electron에서 basic_text 거부**를 확인했고 암호화 저장/복구는 합성 AES 공급자로 검사했다. 이를 실제 키링 재시작 성공으로 표시하지 않는다. Windows/macOS 미실행.
- 전체 UI/초기화 실패 검사는 기존처럼 Unix socket 불가 때문에 단일 인스턴스 잠금만 모의한다. X11은 인증된 Xorg dummy의 루프백 TCP로 제공했다. sandbox 해제 인자를 추가하지 않았다.
- P0-03b2: 인증 입력·복구 UI, 모델 ID/필수값·ZIP 해제 한도·큐 취소 복구·새 프로젝트 저장 호환. 실호출은 사용 계정·요청 수·Anlas 상한·중지 조건을 정한 별도 범위다.
- 이 기능 브랜치에서는 directory package를 다시 만들지 않았다. PR #9 보완의 실제 package 자원 경로/사본 검사는 [별도 기록](2026-11-21-pr9-followup.json)이다.
