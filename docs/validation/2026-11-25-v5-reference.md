## 실제 Electron

최종 제품 빌드를 사용한 Linux 헤드리스 검사다. 단일 인스턴스 잠금은 검사에서만 모의 처리했고 `--no-sandbox`는 명시적인 임시 검사 실행 인자다. 제품 sandbox/설정은 바꾸지 않았다. 아래는 새 프로필/합성 PNG·가짜 토큰/루프백 ZIP이다.

| 실행 | PID | 체크 | 루프백 HTTP |
| --- | ---: | ---: | ---: |
| 참조(reference/reopen/offline) | 3 | 6+3+14=23 | 3 |
| 기존 무참조(create/reopen/offline) | 3 | 30+3+14=47 | 3 |
| 실제 ASAR 참조(generation-reference) | 1 | 6 | 3 |
| 합계 | 7 | 76 | 9 |

최종 실행에서 실제 NovelAI 계정 호출0·원격 요청0·renderer 오류0, 네이티브 종료·원본 프로필 생성0을 확인했다. 이전 중간 실행도 있었으므로 위 수치를 이번 작업 전체에서 발생한 모든 루프백 요청의 총합이라고 주장하지 않는다.

- 파일 선택으로 참조 카드/전송 미리보기/5 Anlas 안내가 뜨며 전송0회·메타데이터 창 열림 없음.
- 카드 드롭은 참조로 처리하고 이미지 교체 때 화풍·강도2.5를 유지함.
- 한 번 누른 생성은 실제 main transport→ZIP/PNG→worker 경로로 결과1개/manifest5/참조 초안·실제 본문 해시를 기록함.
- 기존 묶음 확인이 참조 역할/강도·비용을 표시함. 총2회 큐의 마지막 응답 저장에 잠금을 주입해 pending을 만들고, 이번 결과만 새 프로젝트로 보관하면서 참조 원본/파생도 옮김. 네 번째 요청 없음.
- 새 PID에서 결과/참조 미리보기를 요청0회로 복원함. 오프라인·PNG 일반/알파 메타데이터·라이브러리 재열기/undo/휴지통·23명 경고 회귀도 통과함.
- 390px에서 참조 카드와 작업실 가로 넘침 없음. ASAR 화면 캡처도 확인했으며 검사용2픽셀 PNG라 품질/실제 참조 효과 증거로 쓰지 않음.
- ASAR는 app.isPackaged=true·실행 전후 archive hash 동일·프로필 격리를 확인함. worker는 제품 ASAR 내부 번들이며 하네스만 loopback inspector로 주입함. 기존 기동의 빈 TOKEN.txt ENOENT/SharpElectronLinux 경고는 stderr에 남았고 renderer 오류/검사 실패로 이어지지 않았음. 사용자 토큰 파일을 읽었다는 뜻이 아님.
