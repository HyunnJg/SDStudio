## 실제 Linux Electron

임시 프로필·합성 PNG/가짜 토큰·루프백 응답만 사용했다. 단일 인스턴스 잠금은 검사에서 모의, headless/no-sandbox 인자는 검사 전용이다. 제품 sandbox는 변경하지 않았다.

| 실행 | PID 수 | 체크 | 루프백 HTTP |
| --- | ---: | ---: | ---: |
| 기본 생성/재열기/오프라인 | 3 | 33+4+15=52 | 3 |
| 참조 생성/재열기/오프라인 | 3 | 9+4+15=28 | 3 |

| ASAR 참조 생성 | 1 | 9 | 3 |

위는 선택한 통과 실행들의 합계다. 중간 실행/실패/재실행도 있었으므로 이번 작업 전체의 HTTP 총수로 주장하지 않는다. 큐/오류 검사는 참조 카드 크기·caption 이름/바이트 표시와 재사용 후 문맥 재검사 같은 마지막 화면 보완 전 빌드이며, 보완 뒤에는 기본/참조6PID·80체크와 ASAR2PID·42체크를 재실행했다. 마지막 검토에서 발견한 새 입력/재열기 프리셋 표시 잔류를 renderer 입력 세대로 보완한 뒤 전체363건·범위 lint/tsc·renderer/package를 다시 검사하고 기본3PID52체크/ASAR33체크를 다시 확인했다. 최초 저장은 같은 입력 세대를 유지한다. 모든 선택 실행에서 실제 NovelAI0·외부 요청0·renderer 오류0, 정상 native 종료와 원본 프로필 생성0을 확인했다.

확인한 동작:

- 데스크톱 새 작업실 직접 시작. 씬 선택/프로젝트 버튼 한 곳, 반복/결과가 직접 보임. 일상 설정 노출/부가 설정 접기, 프롬프트 탭 원문 유지, 스크롤 중 생성 버튼 hit-test.
- 23/28스텝 단일 클릭·29스텝 확인/취소·더블 클릭 중복 방지, 전송 중 취소와 서버 처리 불확실성, 응답 후 저장 실패→네트워크 없는 새 프로젝트 저장-only.
- 생성 상태 DOM 변화를 수집해 내부 저장/준비/적용 성공 문장이 다시 나타나지 않음을 확인. 라이브러리 저장 후 저장 표시/적용 이름을 확인하고 적용/undo/휴지통은 별도 상태로 유지.
- 공통 선택/드롭에서 목적을 고르기 전 전송0. 메타데이터 취소·항목별 적용·seed0·Stealth PNG·늦은 읽기 폐기 회귀. V4.5는 로컬 가져오기와 V5 참조 가능 여부를 구분.
- 캔버스 원본 Blob 다운로드 링크·저장된 PNG의 메타데이터 재사용을 확인했다. 참조 재사용도 생성 없이 기존 역할/강도를 유지한다. OS 다운로드 대화상자를 사람이 조작한 검사는 아니다.
- 세션 최초 참조 비용 확인에서 취소0회, 다시 확인 뒤1회, 같은 세션 다음 생성은 추가 창 없이1회·상시+5 Anlas 배지. 큐1회는 기존 비용 확인 뒤 실행해 세 번째 응답 저장 실패→복구, 네 번째 전송 없음.
- 429→이어가기→TIMEOUT/저장 실패, 충돌 씬 제외/미전송 이어가기, 폴링 지연 방어와 상태 복구를 기존 엔진/실제 UI로 재검사.
- 30개 UUID가 같은 합성 PNG를 참조하는 갤러리에서 초기4회 IPC, 스크롤/선택/복사 후 새 프로젝트만 읽기·URL 해제. 디스크 지연/120장 메모리 피크 측정은 아니다.
- 390px 입력/캔버스/서랍과 가로 넘침 없음, dark/light 완료·비활성·취소 후 버튼 계산 색 확인. 참조 카드·고정 버튼의 실제 캡처도 열어 확인했다. 2픽셀 합성 이미지는 화질 근거가 아니다.
