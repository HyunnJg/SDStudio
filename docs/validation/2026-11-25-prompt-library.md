## 실제 Electron

명시적 `SDSTUDIO_SMOKE_HEADLESS=1 SDSTUDIO_SMOKE_NO_SANDBOX=1`의 일회용 검사 프로세스다. 제품 sandbox/연결/토큰 설정은 바꾸지 않았다. 파일 선택은 합성 FileList/DragEvent 주입이며 OS 파일 선택창을 사람이 조작한 검사가 아니다.

일반 create/reopen/offline 흐름에서 기존 생성/취소/결과 저장 복구·갤러리·테마·메타데이터 회귀를 유지하고 라이브러리 검사를 추가했다.

- 메인 현재 입력 캡처→저장(작업실 변화0)→명시적 적용→undo→덧붙이기(기존 품질/UC 유지)→undo.
- 프리셋 휴지통/복원, 저장하지 않은 편집의 앱 닫기 차단과 명시적 편집 버리기.
- 캐릭터 새 카드 생성과 기존 UUID 대상 적용(중복 카드0), 다른 프로세스에서 저장한 라이브러리 재열기.
- V3 합성 JSON 후보 미리보기/텍스트 저장,390px dialog의 수평 넘침 없음, 프로젝트 교체 뒤 같은 라이브러리 유지. 전후 프로젝트 UUID/리비전 목록은 동일해 라이브러리 저장이 프로젝트를 자동 저장하지 않음을 확인한다.
- PR37 후속으로22개 실제 입력+기다리는 카드에 입력해23개가 되면 패널 경고/생성 비활성, 해당 카드를 끄면 텍스트를 보존하며 생성 버튼이 복귀하는지 검사한다.

최종 일반 create/reopen/offline은30/3/14체크, 캐릭터/재열기/offline은9/3/14체크로 **6PID·73체크**를 통과했다. 모든 PID의 원격 요청0·renderer 오류0·정상 네이티브 종료를 확인했다. 생성 루프백은 각 온라인 경로3회씩 총6회이며 라이브러리에서 실행한 생성은0회다. PID별 체크/명령과 CI는 PR 본문에 해당 head 결과로 기록한다. 합성 루프백은 기존 생성 경로 확인용이고 라이브러리/가져오기 자체의 생성 요청은0회다. 실제 NAI 생성0회이며 실서버 결과와 출력/과금 동일성을 검증한 것이 아니다.

## 한계·후속

라이브러리는 단일 앱의 직렬 쓰기를 전제로 하며 외부 여러 writer의 OS 잠금은 없다. fsync/rename 뒤 오류가 나면 교체 여부를 새로고침으로 확인한다. Windows 디렉터리 fsync/전원 손실, 사용자 V3 파일, Windows/macOS GUI·실제 OS 드래그, V3 모든 워크플로우·이미지/설정 변환은 미검증/미지원이다.

V3 메뉴는 기존 도구로 구분했으며 기능/파일/코드를 완전히 제거하지 않았다. 새 프리셋 공간을 사용한 뒤 미이관 인페인팅·선별·조각 편집의 후속을 정한다. 이미지 참조 전송은 다음 별도 범위다.
