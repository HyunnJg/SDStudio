## P3 — 배포 정리

- 릴리스 fuse 후보: RunAsNode/EnableNodeCliInspectArguments 제한, NODE_OPTIONS 정책 및 필요한 플랫폼별 ASAR 보호 검증. 현재 inspector 주입 스모크의 대체/검사용 빌드 분리와 함께 결정하며, 제한 빌드에서 디버거 포트·대체 Node 진입이 비활성인지 실측한다.
- 용량 후보: 소스맵 별도 보관과 sharp 헤더/소스 제외. 오류 진단·런타임·고지/소스 자료 보존 조건을 확인한 뒤 독립 PR로 검사한다.

- CI 후보: 수집기 재실행 후 sourceFiles/자산/lock payload 비교. 수집 시점의 gitHead/dirty는 별도 검증하여 자기 참조/HEAD 변경으로 인한 오탐을 피한다.

- 포크용 앱 식별자·업데이트 안내·배포 위치를 정리한다. 루트 `package.json`의 원본 `build.publish.owner`도 포함한다. 개발 데이터 격리는 P3까지 미루지 않는다.
- 실제 검증한 OS만 지원한다고 표시한다. 원본 CI를 그대로 성공 가능한 배포 경로로 가정하지 않는다.
- 패키징·서명·릴리스·Pages는 개발 빌드와 구분한다. 공개 배포 전에 포함 자산과 고지 자료를 확인한다.

## 작업 가져가는 방법

`STATUS.md`에서 다음 작업을 고르고 기준 SHA, 작업 ID, 수정 범위를 PR 설명에 남긴다. 검토만 할 때는 [검토 양식](reviews/TEMPLATE.md)을 사용한다. 완료 표시에는 실제 실행한 검증 근거를 연결한다.
