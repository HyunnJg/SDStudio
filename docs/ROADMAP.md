# 작업 계획

현재 계획은 작은 변경 단위로 검토하기 위한 초안이다. 일정과 지원 범위의 확약은 아니다.

## P0 — 기존 상태를 재현하고 확인한다

| ID | 작업 | 선행 조건 | 완료 기준 | 상태 |
| --- | --- | --- | --- | --- |
| P0-00 | 포크·공용 문서·검토 양식 준비 | 없음 | 원본 이력이 연결되고 다른 AI가 다음 작업을 식별할 수 있음 | 완료 |
| P0-01 | 설치·빌드 기준 수립 | P0-00 | 사용 Node/npm/OS, 네이티브 도구, 설치·빌드 결과와 실패 원인을 기록. 재현 가능한 최소 명령 확보 | 대기 |
| P0-02 | 원본 외부 서비스·테스트 실행 경로 점검 | P0-00 | IP 확인·업데이트·로컬 AI 시작 경로 확인. 가짜 백엔드로 비과금 UI 검증 가능 | 대기 |
| P0-03 | NovelAI 모델/API 호환성 조사 | P0-00 | 공식 자료와 확인 날짜를 기록하고 모델·파라미터·응답 형태를 정리. 가짜 응답으로 변환 검증 | 대기 |
| P0-04 | 라이선스·고지 자료 정리 | P0-00 | 원본 및 두 서브모듈의 고지 자료·미확인 자산을 구분. 추가 코드 도입 기준 확보 | 조사 시작 |

P0-03의 문서 조사와 비과금 검증은 실제 계정으로 생성에 성공한 것과 구분한다.

| ID | 작업 | 선행 조건 | 완료 기준 | 상태 |

## P2 — 반복 생성 작업 개선 후보

| ID | 후보 | 검토할 효용 | 완료 기준 |

위 기능은 후보이며 P1 및 라이선스 검토 결과에 따라 우선순위를 정한다.

## P3 — 배포 정리

- 포크용 앱 식별자·업데이트 안내·배포 위치를 정리한다.
- 실제 검증한 OS만 지원한다고 표시한다. 원본 CI를 그대로 성공 가능한 배포 경로로 가정하지 않는다.
- 패키징·서명·릴리스·Pages는 개발 빌드와 구분한다. 공개 배포 전에 포함 자산과 고지 자료를 확인한다.

## 작업 가져가는 방법

`STATUS.md`에서 다음 작업을 고르고 기준 SHA, 작업 ID, 수정 범위를 PR 설명에 남긴다. 검토만 할 때는 [검토 양식](reviews/TEMPLATE.md)을 사용한다. 완료 표시에는 실제 실행한 검증 근거를 연결한다.
