## 판단

**개인 실사용은 진행 가능하다. 구 편집기 완전 제거와 공개 배포는 수정 후 진행을 권한다.** 첫 버전의 목표는 저장한 조합으로 촬영하고, 고른 컷을 남기고, 다음 날 빈 컷만 다시 찍는 것이다. 현재 가장 큰 공백은 새 모델이나 편집 도구의 수보다 이 작업을 끊었다가 이어가는 데 있다.

### 촬영 한 세트의 재개

두 인물 × 세 표정 × 두 장을 실제 조합 생성 함수와 큐·저장소로 진행했다. 전송 함수에서는 합성 PNG를 반환했다. 결과 12장 중 서로 다른 다섯 씬에서 한 장씩 선별했다. 저장소를 다시 열어 선별 5개와 누락된 `b · anger` 한 조합을 확인했다. Windows 패키지의 ASAR를 이 프로필로 새로 기동하고 프로젝트를 열었을 때 버튼에는 ‘반복 생성에서 예약할 씬을 선택하세요’가 표시됐다. 여섯 씬을 다시 체크하자 ‘예약 대상 중 선별 없는 씬 1개 다시 담기’로 바뀌었다. 선별 데이터는 온전히 보존됐다.

### 생성 중 강제 종료

각각 새 임시 프로필에서 두 건을 예약하고 첫 요청의 처리 시점에 시험용 Node 자식 프로세스를 종료했다. 실제 생성 서비스·저장소와 로컬 합성 서버를 사용했다. 각 실험에서 서버에 도달한 요청은 한 건이었다. 새 서비스에서 남은 큐와 메모리의 미저장 결과는 모두 비어 있었다.

| 종료 지점 | 재개방 후 갤러리 | 디스크 PNG | 쓰기 잠금 |
| --- | ---: | ---: | --- |
| 서버 수신 후, 응답 전 | 0 | 0 | 없음 |
| PNG 응답을 받고 저장 함수에 들어간 직후 | 0 | 0 | 없음 |
| PNG 동기화 후 프로젝트 기록 교체 직전 | 0 | 1 | 남음 |
| 저장 완료 후 호출자에게 성공 반환 직전 | 1 | 1 | 없음 |

이 결과로 실제 서버의 과금 여부는 판별할 수 없다. 재시작 후 자동 중복 전송은 관찰되지 않았다. 남은 잠금을 복구할 때는 다른 실행 주체가 쓰는 중인지, 프로젝트 기록과 PNG가 어느 단계까지 맞는지도 확인해야 한다.

## 잘 유지해야 할 부분

- 평소에는 새 작업실에서 생성·선별·마스크 편집을 끝내고, 공급자 설정과 바이브 에디터는 필요할 때 연다. LLM 제안을 검토하는 단계와 유료 이미지 생성 승인을 계속 분리한다.
- 구 V3 즐겨찾기 PNG, 원본·마스크, 프리셋·조각, 씬과 활성 조합을 이어 쓸 수 있어야 한다. #62에서 구 편집기가 실제로 쓴 합성 세션을 새 작업실에서 검증했다. 미선별 원본은 원래 위치에서 찾아 다시 쓸 경로를 제공하는 편이 좋다. 대진표·비활성 후보의 재편집은 실제 수요가 생길 때 판단한다. [기존 이관 결정](../DECISIONS.md#d-084-구-v3-편집기가-저장한-선별과-마스크로-이관을-검증한다)
- 새 작업실에서 파일로 읽는 이관과 구 편집기에서 직접 연 세션은 수명주기가 다르다. 구 편집기로 열면 세션이 마이그레이션·종료 시 저장 대상이 될 수 있다. 구 화면 제거 뒤에도 읽기 전용 이관 검사와 구 writer가 만든 합성 입력을 보존한다.
- 프로젝트 복사는 선별을 함께 복사한다. 과거 리비전을 새 프로젝트로 복구하면 선별은 비어 있다. 이미 테스트에 명시된 계약이므로 복구 시점에 이를 안내하는 것으로 충분하다. [저장소 검사](../../src/__tests__/resultPicks.test.cjs)

## 불확실한 부분

- 이번 시험은 합성 이미지와 격리 프로필을 사용했다. 강제 종료는 프로덕션 클래스를 사용한 자식 프로세스 수준이다. OS 전원 차단, 실제 계정 과금, 사용자의 장시간 작업, 실제 구 설치본 위 업데이트·제거는 미실행이다.
- 구 화면은 지연 로드되지만 구 서비스 일부는 앱 시작 때 생성된다. 태그 검색 네이티브 모듈은 메인 프로세스에서 직접 로드한다. 기본 작업실 주 프롬프트와 구 편집기의 자동완성 사용처를 구별하고, 제거 후 앱 기동과 가져오기를 확인해야 한다. [앱 조립](../../src/renderer/componenets/App.tsx) · [메인 진입](../../src/main/main.ts)
- 기본 전체 타입 검사 `tsc --noEmit`은 기존 `libsodium-wrappers` 자동 타입 탐색 오류 TS2688에서 중단됐다. 해당 명령으로 앱 전체 타입 건전성을 확인하지 못했다.
- Windows 패키지 고지 사본 검사와 재배포 범위 판정은 별개다. 저장소에는 native ISC 고지 원문, 태그 DB·자산 출처, 일부 동봉 바이너리 검토가 남아 있다. [기존 라이선스 검토 기록](../LICENSE_REVIEW.md)

## 다음 작업 제안

1. 마스크 제외 선택과 기동 시 PNG 복제를 각각 작은 회귀 수정으로 닫는다. 새 작업실에 연결된 읽기 경로를 유지한다.
2. 마지막 촬영의 씬 범위를 다시 열 수 있게 한다. 위 12장 시나리오에서 빠진 한 조합만 확인·재예약하며, 과거 프로젝트는 기존 수동 선택으로도 열린다.
3. 유료 큐를 장시간 맡기기 전에 수신 PNG와 전송 상태의 복구를 확보한다. 중단한 네 시점에서 확인된 결과, 응답 미확인, 미전송을 구분한다. 재시작만으로 새 요청을 보내지 않는다.
4. 개인 실사용 중 이사·백업이 필요하면 작업 세트 복원을 우선한다. 구 편집기 제거는 원본 접근·태그 검색·가져오기 회귀가 통과한 뒤, 공개 배포는 실제 업데이트 설치와 고지 범위를 확인한 뒤 결정한다.
