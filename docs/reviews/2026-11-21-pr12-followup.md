# PR #12 전달 의견 처리

기준 `0fdfc3f`. Gemini·Claude 의견을 운영 코드와 대조했고 PR #12를 `ab286f2`로 병합했다. 아래 보완은 다음 작업 브랜치에 별도 수정 커밋으로 둔다.

| 의견 | 처리와 근거 |
| --- | --- |
| V3 로그인과 새 토큰 보안 정책 충돌 | D-029. 기존 기능/파일 호환을 유지하되 환경설정에 이메일·비밀번호 사용·TOKEN.txt 평문 저장을 명시. 상단의 비밀번호 로그인 유도를 V3 상태 표기로 바꿈. 새 API 토큰만 보관한 실제 패키지 화면과 경고 표시 확인 |
| 재시작 차단 원인 불명확 | V3 실행/종료 중·V3 예약·새 작업실 대기열로 구분. V3 0개라도 진행 promise가 남으면 기다려야 함을 안내. 저장 전후 확인 유지. 단위 10건 및 실제 재시작 하네스에서 종료 중 안내 확인 |
| quit 취소 시 restarting 고착 | 현재 close·before-quit 등록을 조사. 제어된 close는 저장 분기만 건너뛰고 로컬 AI 정리/토큰 lock은 취소하지 않음. 실제 Linux 재시작 재검증. 예약된 relaunch는 남는데 타이머만 해제하는 복구는 추가하지 않음. 추가 취소 핸들러 도입 전 수명 정책 검증을 P3에 등록. 취소 복구 테스트 완료로 표시하지 않음 |
| 배지 바로가기·저장/재시작 통합 | P1 일반 설정 동선 정리 후보로 유지. 지금은 저장만 한 뒤 나중에 재시작하는 선택과 임시 데이터 소실 확인을 유지 |
| Windows/macOS relaunch 인자/종료 | P3 실기 목록에 명시. Linux에서 실제 두 번 재시작 통과가 다른 OS 검증을 대체하지 않음 |
| 다음 ZIP/모델 연결 | D-030의 제한된 메인 응답부터 구현. 공식 스키마 재확인 후에도 모델 ID/필수값은 미확정. 실제 계정·비용 범위 없는 호출은 하지 않음 |

새 모듈과 전송의 전체 기한/취소·압축 한도·CRC/PNG 바이트 보존은 [별도 검증](../validation/2026-11-21-image-response.md)에 기록한다. 실제 생성 IPC·대기열 바인딩·새 프로젝트 저장 완료와 구분한다.
