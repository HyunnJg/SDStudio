# PR #19 검토 처리 — 저장 worker와 비정상 닫기

- 작성일: 2026-11-22 (Asia/Seoul)
- 대상: `607173ff4d45ddfafed4a9595858dd12a9727466`, 병합 `57e1a277af4aa2c6dd764221cc094b8fbe0e6142`.
- 전달받은 Gemini·Claude 의견을 실제 소스 및 패키지와 대조했다. 전달 원문이 독립 실행 검증을 대신하지 않으며 이번 구현은 D-040이다.

| 의견 | 처리 | 근거/한계 |
| --- | --- | --- |
| renderer crash/unresponsive에서 창을 영원히 닫지 못함 | 채택 | 실제 종료/무응답 이벤트를 상태로 기억하고 native close 때 취소/기다리기 또는 명시적 버리기 선택. 타이머 자동 승인 없음 |
| worker 오류 뒤 일반 I/O 안내와 영구 중지 | 채택 | PROJECT_SERVICE_STOPPED + 수동 저장 기능 재시작. 실패한 쓰기는 재전송하지 않고 목록으로 준비 여부만 확인. 완료 여부는 다시 열어 확인 |
| worker가 ASAR 안에 있어 실행에 실패할 수 있음 | 실측 후 설정 유지 | PR19 기준과 변경 후 Linux 디렉터리 패키지에서 실제 worker 저장·복구·닫기 통과. worker는 ASAR 내부, unpack 파일 없음. Windows/macOS로 일반화하지 않음 |
| Worker 생성 동기 예외 | 채택 | Promise rejection으로 일관되게 고정 중지 코드 반환, 동기 throw 회귀 검사 |
| 개발 TS hook이 cwd에 의존 | 채택 | 모듈 위치 기준 절대 hook 및 TS_NODE_PROJECT. cwd를 테스트 프로필로 바꿔 worker 재시작·저장 검사 |
| 120개 서로 다른 물리 PNG 성능 측정 | 후속 | 기존 성능 검사는 동일 파일 참조임을 계속 명시. 이번에 새 성능 수치를 주장하지 않음 |

실제 패키지에서는 ASAR 수정 없이 inspector로 테스트 하네스를 진입 전에 주입했다. 강제 worker 종료/렌더러 crash는 실제 동작이고, 무응답은 이벤트 주입이며 native dialog 선택만 모의했다. 정상 단일 인스턴스 잠금은 환경 제한으로 모의했다. 이 한계를 검증 기록에 함께 둔다.
