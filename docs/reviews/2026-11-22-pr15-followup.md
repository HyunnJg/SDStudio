## 첫 실제 응답으로 확인한 문제

사용자가 Windows에서 연구 창을 열고1회 전송했다. 공개 허용 필드만 받은 [관찰 기록](../validation/2026-11-22-first-live-observation.json)에 HTTP200, MIME분류other, ZIP flags8/method8/extra0,64KiB에서잘림, 잔액 관찰차이0을 남겼다. 계정 잔액 숫자/계정·토큰·원시 본문·이미지는 저장소에 옮기지 않았다. 개발 환경에서 사용자의 토큰을 받거나 계정을 호출하지 않았다.

기존 연구 capture는 미분류 MIME을 오류로 처리해 정상 ZIP 시작부가 있어도64KiB prefix만 보관했다. 실제 MIME 문자열은 분류 단계에서 폐기돼 현재 알 수 없고, 잘린 ZIP으로 전체 PNG를 검증/복구할 수 없다. 첫 실험이 모델/PNG의 완전한 성공이라는 뜻은 아니다.

연구 entry에서만 acceptZipSignature를 명시적으로 켠다. capture도 켜져 있고2xx 응답이 PK0304로 시작하면64MiB 한도에서 전체를 보관하고 기존 엄격 ZIP/PNG 검사에 넘긴다. 분할 청크의4바이트를 모아 판정한다. HTML/JSON·비2xx·capture미지정/옵션미지정은 기존 거부 정책이다. ZIP 시작부만으로 PNG 성공 처리하지 않는다. 일반 앱의 기본 전송 정책은 확대하지 않았다.

실제와 같은 미분류 MIME/DEFLATE/data descriptor/64KiB초과 합성 응답을 실제 Electron에서 원본 PNG로 검증했다. 결과 기록 없이 재개한 프로필의 잔액 기록/재전송 거부도 확인했다. [후속 검증](../validation/2026-11-22-live-recovery.md), [다음 실험 규칙](../NAI_LIVE_VALIDATION.md).
