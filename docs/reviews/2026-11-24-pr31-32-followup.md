# PR31·32 검토 의견 처리

검토 기준 PR31 `e42318a` / PR32 `62234ed`. 사용자 전달 Gemini/Claude 의견이다. Windows/Linux CI 2/2를 각 head에서 다시 확인하고 사용자 승인에 따라 PR31은 `3b23bf4`, PR32는 `dcdae0b`로 병합했다. STATUS 변경도 충돌 없이 합쳐졌다. 후속 작업은 main `dcdae0b`에서 시작했다.

| 의견 | 처리 |
| --- | --- |
| PR30 미사용 import 기록 정정 | 지적이 맞다. `git show dcf0433:.erb/scripts/async-storage-probe.cjs`와 c6ceb01에서 59행을 확인했다. 구현자가 없다고 기록한 오류를 정정하고 실제 운영 reader/왕복에 사용한 PR31의 변경을 구분했다 |
| 실패한 set과 동시 read | 재현 테스트를 추가했다. 수정 전에는 암호문/세션 두 경우 모두 STORE_WRITE_FAILED, 수정 후에는 보존된 A를 읽는다. set 호출자는 계속 저장 실패를 받는다. 세대가 달라진 read는 CANCELLED, 파일 없음/손상/상위 버전은 읽기 고유 오류다 |
| Linux async 초기화 전 unknown | 공식 문서를 재확인했다. async 공급자와 sync backend 표시의 완전한 대응은 보장되지 않는다. 이번에 unknown을 허용하지 않고 실제 GNOME/KDE·async fallback 검사까지 보수적 거부/미검증 표시 유지 |
| 어두운 테마 panel색 고정 | 기존 동작 유지임을 PR32 검증 문서에 명시했다. 전체 UI에서 주 행동 버튼 색을 의도적으로 정할 때 기대값도 갱신한다 |
| 정확한 서버 MIME | 미확인 유지. 추가 과금 호출이나 키 요청 없이 사용자 로컬 첫 응답 진단에서 추후 확인할 수 있다. V5 생성 성공 보고를 특정 MIME 증거로 바꾸지 않는다 |
| Electron46 | 정확한45.4.1 고정과 설치 gate 유지. 이번 후속과 별도 검토 |
