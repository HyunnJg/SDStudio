# PR #22 검토 처리 — 다음은 기본 바인딩의 선택 씬·반복 큐

작성일: 2026-11-23 (Asia/Seoul). 구현 담당자의 소스 대조·처리이며 새 독립 검토가 아니다.

사용자가 제공한 Gemini·Claude 검토의 기준 head는 `e8708baec3df159ca920f943f552240d1c3041aa`다. 실제 head 일치·mergeable을 확인한 뒤 PR #22를 병합했고, main `ea7a979a4178f1f7a5d2b1afaa68f27d645304df`에서 `work/p1-connected-queue`로 시작했다. 변경 범위는 main의 공통 생성/큐·고정 IPC/preload 타입, ConnectedWorkspace/큐 패널, 해당 합성 단위·Electron/ASAR 하네스 및 문서다. V3·기존 mock 큐·모델 바인딩·프로젝트 manifest 형식은 변경하지 않는다.

| 의견 | 처리 |
| --- | --- |
| open 실패가 이전 PNG 누락일 수 있음을 구분 | PROJECT_CORRUPT 안내에 최근 생성은 정상 저장됐을 가능성·일부 이전 파일 누락/차이·원본 보존·유효 이력의 복사 복구를 명시. 이력이 분실 PNG를 복원하지는 않는다고 안내 |
| worker→main ArrayBuffer transfer | 보류. 이번 큐는 직렬/PNG1건씩이고 복사 비용 병목을 측정하지 않았다. 기존 원본 바이트/소유권 경계를 유지하며 후속 실측 후 판단 |
| controller imageRecords 스냅샷 재사용 | 유지. 외부 파일 감시·무결성 캐시로 확대하지 않음. 명시적 open/copy/recover는 전체 검사, 선택은1개 검사 |
| P1-02b 묶음 확인/중지/실패·미저장 복구 | 구현. 저장된 선택 씬·반복을 메인에서 복사/바인딩하고 확인은 총 요청 수·설정·확정 시드에 대응. 5분 시작 만료·1회 선점. 실행은 직렬이고 실패/중지 후 자동 진행/재시도하지 않음 |
| 새 UI 실제 계정1장 선확인 | 권고는 유지하되 이번 구현/합성 검증의 차단 조건으로 삼지 않음. 새 UI 실계정·정확한 MIME은 여전히 미확인. 키는 채팅으로 받지 않고 필요 시 사용자가 앱 토큰 창에 직접 입력 |

[D-043](../DECISIONS.md)은 반복 우선 순서, 실행 전 전체 고정 바인딩/랜덤 시드 확정, 최신 manifest 결과-only append와 다음 요청의 입력 fingerprint 비교를 결정한다. 와일드카드는 아직 거부하며 실행별 전개를 완료했다고 표시하지 않는다. 입력/예약을 바꾸려면 취소 후 새 확인을 한다. 미전송 작업만 새 확인으로 이어갈 수 있고 실패/취소된 요청을 포함해 자동 재전송하지 않는다.
