# 새 작업실 프로젝트 저장 기반 — P0-03b2

2026-11-22. 런타임 `a7735f982f7a5fba100d866bf0967149a95cd967`. 기준: PR #17 병합 `30d238181d7c4d48262a40e2d1c8be04554ffd07`. 결정 D-037.

이번 범위는 **독립 저장 형식·메인 저장소·신뢰 프레임 IPC**다. 기존 작업실은 계속 메모리 기반 mock이며 저장/열기 버튼·종료 시 저장·대기열/실제 생성 연결은 다음 단계다. IPC가 있다고 현재 화면의 초안이 자동 저장되는 것은 아니다. V3 파일의 읽기/변환/저장 코드는 바꾸지 않았다.

## 형식과 위치

저장 위치는 포크 userData 아래 `projects-v1/<UUID>/`로 고정한다. IPC는 경로를 받지 않고 소문자 UUIDv4와 SHA-256만 받는다. config.saveLocation·TOKEN.txt·기존 V3 세션을 탐색하거나 자동 복사하지 않는다. 폴더는 목록 조회만으로 생성하지 않고 명시적인 create 때 만든다.

| 파일 | 의미 |
| --- | --- |
| project.json | format=sdstudio-workspace, version=1, id, name, selectedSceneId, scenes, images |
| history/<revision>.json | 수정 직전 유효한 manifest의 원본 바이트. revision은 그 바이트의 SHA-256이며 덮어쓰지 않음 |
| images/<sha256>.png | 검증된 PNG 원본 바이트. 내용 해시로 식별하며 재인코딩·메타데이터 추출/변형 없음 |
| write.lock | 프로젝트별 배타적 저장 잠금. 정상 종료 시 제거, 비정상 종료 후 남으면 자동 삭제하지 않음 |
| .next-<UUID>.json | 원자적 교체용 임시 파일. 정상 실패 경로에서 정리, 프로세스 강제 종료 때 남을 수 있음 |

V3 Session.version=1과 새 format/version은 관계없다. 같은 파일의 자동 승격이나 V3 → 현대 모델 변환을 구현하지 않는다. 포크 버전을 되돌려도 원래 V3 파일은 그대로이며 새 프로젝트는 별도 폴더에 남는다. 새 형식을 모르는 앱이 읽거나 변환한다고 가정하지 않는다.

## 저장할 내용

씬별 편집 초안과 선택 씬을 저장한다. `snapshotWorkspaceScenes`로 현재 편집 초안을 합친 명시적 스냅샷을 호출자가 제공해야 한다. 배열 순서·비활성 캐릭터·논리 격자 칸·무작위/고정 모드·고정 시드 문자열 0을 보존한다. 빈 시드/스텝 등 편집 중인 문자열과 `|`도 저장할 수 있다. **저장 형식 검사와 생성 가능 여부/API 규격 검사는 다르다.** 저장 시 요청 투영·랜덤 시드 생성·와일드카드 전개를 하지 않는다.

이미지 기록에는 명시적인 model/sampler/noiseSchedule, 실제 사용 시드 숫자, 당시 초안, sceneId, PNG 해시/크기를 둔다. 이는 향후 생성 연결이 올바른 최종 전개 초안과 식별값을 넘길 전제이며 현재 코드가 실제 API 요청/모델 의미를 검증했다는 뜻은 아니다. 임의 요청 JSON·인증 헤더·전송 오류 원문을 저장하지 않는다. 전체 모델별 요청 body의 완전한 provenance는 실제 바인딩 단계에서 별도 결정한다. 삭제된 씬의 과거 이미지 기록도 잃지 않도록 manifest 저장은 기존 images를 유지한다.

허용 키만 검사하고 알 수 없는 키·중복 ID·잘못된 enum/격자·넓은 경로 문자열은 거부한다. 텍스트 내용 자체는 사용자가 작성한 프롬프트로, 사람이 자격증명을 프롬프트에 붙여 넣는 행위까지 판별하는 도구는 아니다. 파일은 비공개 데이터로 취급한다.

로컬 한도: manifest 2 MiB, 씬 60개, 씬당 비활성 포함 캐릭터 32개, 이미지 기록 120개, PNG 하나 32 MiB·16,777,216픽셀, 이미지 합계 256 MiB. create 프로젝트 수/한 프로젝트 이력은 최대 1000개 정책이다. 이력·PNG를 자동 정리하거나 삭제하지 않는다. 보관 이력을 포함한 디스크 총용량 제한이나 압축 저장은 구현하지 않았다. 변경 전 텍스트 양을 제한하고 최종 UTF-8 JSON 바이트 수도 검사한다.

## 쓰기·충돌·복구

1. UUID/리비전/내용을 검사하고 `wx` 잠금을 얻는다. 다른 저장이나 남은 잠금이 있으면 PROJECT_BUSY다.
2. 현재 프로젝트·참조 PNG의 해시/크기를 확인하고 호출자가 읽은 리비전과 비교한다. 다르면 PROJECT_CONFLICT로 거부한다. 목록은 manifest 메타데이터만 검사하며 모든 PNG 무결성은 open 때 검사한다.
3. 수정 전 manifest를 history에 동일 바이트로 보존하고 새 manifest를 임시 파일에 `wx`/0600으로 쓴 뒤 fsync·rename한다. 정상 실패 경로는 원본·이력을 유지하고 잠금/임시 파일을 정리한다.
4. Linux에서 신규 폴더와 이력/이미지/manifest 디렉터리도 fsync한다. Windows는 이 방식의 디렉터리 fsync를 건너뛴다. Windows rename/ACL과 전원 차단 내구성은 실측하지 않았다. rename 뒤 디렉터리 fsync/잠금 정리 등이 실패하면 오류여도 교체됐을 수 있으므로 다시 읽어 리비전을 확인해야 한다.
5. 손상·미지원 버전·한도 위반이면 읽기/저장을 거부하고 원본을 보존한다. 자동 이력 선택·자동 파일 교체는 없다. `recover(id, revision)`은 사용자가 고른 유효한 이력과 PNG를 검증해 **새 UUID의 복사본**을 만든다. 손상/상위 버전인 원본은 그대로 둔다.

PNG는 기존 응답 해석기의 PNG 구조/CRC/크기 검사를 재사용하고 원본 바이트를 저장한다. 같은 내용 해시 파일이 있으면 바이트 동일성을 확인한다. open/recovery는 참조 파일의 해시와 크기를 확인한다. 이미지가 손상/분실됐으면 manifest 이력만으로 복원할 수 없고 명시적 오류가 난다. PNG 픽셀·IDAT 전체 디코딩이나 이미지 품질/메타데이터 의미 확인은 하지 않는다.

파일은 같은 fd에서 lstat/fstat 대응·일반 파일/최종 심볼릭 링크 거부·상한 읽기를 한다. 관리하는 profile/projects/project/images/history 경로의 링크도 거부한다. 이미 실행된 포크 프로필 보호에 더하는 경계이며 같은 사용자 권한의 악성 프로세스와 경로 교체 경쟁 전체를 봉쇄하는 파일시스템 샌드박스라는 뜻은 아니다. 쓰기 실패/강제 종료 때 참조되지 않는 이미지·임시 파일/부분 이력이 남을 수 있다. 원본 보호를 위해 자동 제거/잠금 강제 해제는 제공하지 않는다. 별도 복사·복구 UI를 붙일 때 안내한다.

## IPC와 후속 화면

`window.electron.projects`의 list/create/open/save/history/recover만 제공한다. 기존 인증과 같은 현재 메인 창·최상위 프레임·승인 문서 검사를 재사용한다. 로컬 파일 기능이라 오프라인에서도 허용한다. 반환 오류는 고정 PROJECT_* 코드이며 OS 예외 원문/절대 경로를 반환하지 않는다. 기존 범용 파일 IPC까지 이 정책으로 전환한 것은 아니다.

PNG add/read는 **메인 내부 메서드**뿐이다. 렌더러가 임의 PNG·파일 경로·이미지 바이트를 올리는 IPC를 열지 않았다. 일반 앱은 준비된 IPC를 등록하지만 자동 저장/생성/수집은 하지 않는다. mock의 SVG 예제 결과를 실제 PNG로 저장하지 않는다.
